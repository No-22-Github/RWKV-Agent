# 转入语料准备前的离线核验（2026-09-20）

本轮只离线核验：没有新增 API 请求，没有训练，没有改动冻结评分器或历史 ledger。完成全部 36 题的轨迹归档、当前成品语料盘点和独立的 k 次结果聚合工具。讨论中提出的训练策略是待检验方案，不作为已证明的原因或训练收益。

## 可以停止什么，尚未证明什么

支持停止继续加大当前推理预算的实验：10→30 没有新增成功，且三个相同前缀案例清楚展示继续运行后的错误。不能把这件事扩大成“预算对任何模型/配置都无用”，也不能说 judge、wire、目录的解释空间已经全部排空。已测的是具体设置下的有限干预。

“简单操作在，组合和自我一致性不在”仍过于二分：梯度题自身也含多步组合，P0A2 实际就用了三次工具调用；反过来，36 题里有许多轨迹尚未到计算/规则解释阶段。当前更准确的描述是：模型在一些受限任务上能完成取证与回答，但真实工作区任务中的来源选择、协议输出、工具语义、证据解释、交付和停止不稳定。

四条例子也不能证明“全部是策略先验，绝非知识/推理问题”。code-0002 的计数错误、tab-0003 的唯一性和汇总错误，都涉及内容处理；trace 只能显示行为与错误，不能辨识潜在能力是否完好。SFT 与 state 是不同容量/干预方式，哪种能修、泛化多大需要后续训练对照。策略轨迹是合理训练目标，不是训练效果保证。

## 语言判据：42 是候选值，不是 42 个可机械替换的补丁

上轮 42 个候选值包含澄清、拒绝、错误恢复及本地化事实。此前做出的决定是拆分语义和语言维度，没有给出一个已经验证的双语 scorer。把“列出候选”说成“只差应用”跳过了最关键的一步。

建议的落地边界如下；本轮尚未变更评分规则：

1. 保留旧 frozen scorer，保证训练前后有同一把尺子。
2. 建立明确版本的语义诊断层，分别判断是否询问正确缺参、是否准确描述工具失败、是否正确拒绝不可执行操作、事实是否一致。不能只给 path / keyword / unavailable 等词做 substring OR：否定、转述、幻觉和错误对象可能同样含这些词。
3. 单列语言遵循；文件名、标识符、实体身份、显式纯值/输出格式契约继续检查。
4. 对任何新语义判据先准备正例、语义近似但错误的反例、双语等价例；用冻结的训练前输出和训练后输出一起重判，不能只改训练后的成绩。

如果下一步仅要一个低成本可执行方案，可先用固定人工 rubric 对小型冻结诊断集盲审，保存证据和判断；不把未经校准的词表扩张当成正式通过率。

## k=3 支持已补齐；没有伪造第三次运行

`ledger.py` 里 `pass_all_k=None` 的注释声称稍后填充，但当前实现没有聚合它；matrix 只是合并运行的均值。不是把某个 None 改成一个数字就完成。`pass_all_k` 属于明确的一组重复运行，不是任意单次 run 的属性。

新增 `bench/workbank/tools/replicate_summary.py`，纯离线、输出独立 JSON，不改 append-only ledger：

- 默认必须恰好三个不同 run_id，每份 run.json / summary.json ID 一致，全部题与 turns 齐全。
- frozen cases、model、sampling、完整 harness（含评分器、预算、wire、并发等）、state 标记、binary SHA 必须相同；基础设施错误不静默记成模型失败。
- 每题保留三次布尔向量，输出 pass_mean、pass_all_k、pass_any_k、unstable_cases、输入摘要和配置摘要。
- 不把 max_steps=10 和 30 当两次 replicate；不把同一运行文件重复传三遍。

```sh
python3 bench/workbank/tools/replicate_summary.py \
  RUN_K0 RUN_K1 RUN_K2 --k 3 --out REPLICA_GROUP.json
```

5 个针对性测试通过，覆盖 all/any 与均值、缺失/重复运行、预算/题目改变、缺题、基础设施错误；另用本轮真实 10/30 运行验证被拒绝聚合。没有发起新的三轮推理，也没有输出虚假的 k=3 基线。

两个观测之间的 0→1 只说明这次观测差一题，**不能估计“噪声就是 ±1”**。k=3 的 all/any 是描述性稳定性指标，不是显著性检验、置信区间或 pass@k 估计。训练前后须采用同等的 k、同题逐项比较，继续分开官方与语义诊断两层，不能用 any 的提升遮住 all 的退化。

## 可直接采用的语料设计约束

以下是有证据支持的覆盖项，尚不固定条数，不宣称提升幅度：

- 协议：纯工具动作、合法参数、明确终答；示例应使用实际训练/推理 wire。混合解说与调用是本次 6 题首轮未执行的重要可观察形状。
- 来源与参数：本地/网页选择，已知路径直接读取，目录与文件区分，schema 校验错误后修正参数，内容搜索与文件名发现区分。
- 证据与计算：一次充分的批量查询、唯一键计数、按回执值计算、单位/覆盖范围/过滤条件、推理不足时合理继续。批量不应压倒 API 的分页/速率/权限约束。
- 空结果：无匹配、文件不存在、校验失败、权限拒绝、网络错误分开；只有搜索范围和方法足以支持结论时才声明不存在。“空就一定换工具”本身也会教出过度调用。
- 交付：真实写入指定文件、保护不应修改的内容、满足脚本执行验收；绝不把一句 DONE 当成产物验证。
- 停止：证据充分后停止并遵循答复契约；保留需要继续取证的对照例，避免学成一律早停。
- no-call：分别覆盖不相关工具、缺参澄清和信息不足；600 是已有数量，不是效果结论。

“忠实回执”不要求在用户可见答案里逐条复述数字，否则与纯值契约直接冲突，也可能教长输出。教师样本应由程序/工具验证中间运算和终答，必要的中间结构按当前 wire 支持方式表达，最终回复仍遵循用户契约。

模型的错误轨迹用于选教学场景和构造对照，不直接作为正向 SFT target。只监督经过验证的正确动作/回答；若另做偏好训练，显式区分 chosen/rejected 数据格式。用新的任务实例和 fixture 生成教学数据，保持评测题隔离，不能把这 36 道题原样补答案塞进训练，再拿同题涨分当泛化。

长度以最终 rendered 训练文本的真实 token 数验收，包含目录、历史、回执、终答、prefill/mask 边界。上轮的 419→565→1138→1294 是逐次请求前缀长度；累计请求 token 是推理成本，不是训练样本长度，也不能由两个案例推导所有 work 轨迹都为 1300–1700。30 步案例单次输入已超过 6000；当前 v1 成品也有贴近 4096 的样本，需逐条计数。
