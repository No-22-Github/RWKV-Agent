# 训练步数 ↔ 能力：G1K state 三轮训练的剂量-反应（2026-09-21）

**一句话**：同一系列内，通过数随训练步数上升（B：78 步 1/40 → 156 步 6/40 → 234 步 15/40，final 14/40，基座 3/40）；**跨系列看，决定成败的不是步数而是状态漂移幅度**——中位 RMS ≥0.84 的 12 个点全部 0/40（A2 的 0.84–1.06、A 的 3.68–3.83），只有 RMS 0.13–0.18 的 B 系列出现通过。同时，**"焊接"（复现语料首步）与"能力"是两条解耦的轴**：焊接度最高的 A-270（精确 11/36，超过常数基线 9/36）通过数为 0，而焊接度略低的 B-final（精确 8/36）通过 14/40。

## 4. 读法一：焊接 ≠ 变强

把三轮的焊接率与通过数放在一起看，**焊接度不预测通过数**——在崩溃区甚至是反向的（焊接越高、通过越少），在可用区两者也不单调（B-234 与 B-390 的精确焊接同为 8–9/36，通过数 15 vs 11）：

| 点 | 焊接精确一致 | workbank | canary |
|---|---:|---:|---|
| A-270 | 11/36 | 0/40 | 不可读 |
| A-135 | 9/36 | 0/40 | 不可读 |
| B-390 | 9/36 | 11/40 | 可读 |
| B-468 | 9/36 | 10/40 | 可读 |
| B-234 | 8/36 | 15/40 | 可读 |
| B-final | 8/36 | 14/40 | 可读 |
| A2-108 | 4/36 | 0/40 | 不可读 |
| 零 state | 2/36 | 3/40 | 可读 |

A-270 精确复现 11/36（全库最高，甚至超过"恒选 list_files"的 9/36），但 canary 是词沙拉、通过 0/40；B-final 精确 8/36，却通过 14/40。**首步焊接只是把语料的开场动作写进了时间状态，它既不保证后续步骤正确，也不保证模型还能正常说话。**

这一点也解释了前两轮的错觉：A2-36 的协议有效率高达 0.98、A-270 的是 0.96，看上去"很健康"，实则 canary 不可读、通过 0/40——**协议有效率只说明模型还在按 harness 的格式说话，不代表它在解决问题**。

## 5. 读法二：可用区间的边界

按幅度把 20 个点分三区：

| 区 | RMS 区间 | 观测点 | 通过数 | 说明 |
|---|---|---|---|---|
| 欠训（推测） | ≤0.01 | 上一枚 state-final（0.001，另一套配方：630 行 / lr 1e-5） | 1/40 | 漂移太小，语料策略没装上：首步偏网页、复读链仍在。**只有一个点，不足以断言下界** |
| 可用 | 0.13–0.18 | B-78…B-final（7 点） | 1→6→15→9→11→10→14 | 唯一出现通过的区；协议有效率 0.80–0.97，canary 多数可读 |
| 崩溃 | ≥0.84 | A2（0.84–1.06）、A（3.68–3.83） | 全 0/40 | canary 6/12 不可读；A 全系列词沙拉 |

阈值可操作化：`state_sanity.py` 的三档（ok ≤0.05、WARN ≤2.0、FAIL >2.0）用于拦住 A 那种崩溃；但**能通过 ≠ 可用**——A2 的 0.84–1.06 全部落在 WARN 里且 0/40，所以闸门只用于排除崩溃，行为结论仍要跑评测。

## 6. 代价：workbank 换 BFCL

workbank 的收益与 BFCL 的损失同向增长：训练越久，workbench 类任务越强、通用工具调用越弱（47→13→7）。**B-234 是当前兼顾最好的点（workbank 15/40、BFCL 13/60）**；若必须报通用能力，应取更早 checkpoint 或混入通用工具调用数据。

## 8. 已知缺口与风险

- 每个点只跑一次贪心（n=40），通过数的抖动约 ±2–3 题：B 系列 312/468 的 9–10 与 234 的 15 之间的差可能部分来自抖动；78→156→234 的上升段更可信。
- A 与 A2 两轮共用 `state_out_A/`，同名 checkpoint 会互相覆盖：A 的 step-90（sha256 `268f922e…`）本地文件已被 A2 的 step-90 覆盖，其 RMS 3.815 来自上传前的一次抽样测量（表中已标注），**评测数据本身未受影响**（上传回执记录了当时的 sha256）。
- B 的 7 个 checkpoint 里有 4 个（156/234/312/390）首次上传被网络中断，加显式重试后才成功；批量上传务必带重试。
- B-156、B-234 两次 run 触发了严格 canary 漂移（客户端停止标记之后），已按 `--allow-canary-drift` 记录，并通过数不因此改变结论方向。
- BFCL product 是本仓库的 60 题产品子集，不是官方榜单；A/A2 两轮未测 BFCL，因此"遗忘"曲线的左半段缺数据（只有零 state 47/60、上一枚 49/60 两个参照）。
