# 700 条技术工作区 Agent 语料制作需求单

> **2026-09-20 用户口径修订**：本次交付允许已审查的少量 train 内结构近重复，不要求为凑结构差异重写。具体 13 条及授权见 [保留政策](verification/phase3-retention-policy.json)。下文严格结构新颖性要求对该清单作显式例外；正确性、真实回放、契约、mask/token、精确内容去重及跨 split 隔离门槛继续执行。交付数量 700 指记录数，不宣称 700 个结构独立任务。

版本：workspace-agent-700-v0；日期：2026-09-20。

## 1. 目标与本轮范围

围绕本目录归档的 36 道种子题制作 700 条独立、可执行验证的任务轨迹记录。每条同时交付任务、初始环境、验收规则、正确工具动作、真实工具回执、最终答案/文件结果和来源元数据。

训练目标覆盖：证据来源选择、文件定位、schema/工具语义、正确计算与唯一性、规则优先级、文件与脚本交付、有效恢复、停止和输出契约。已有失败归档用于选教学重点，不把现有模型的错误回答当作正向监督目标，也不把观察到的失败次数直接当训练权重。

本需求单定义数据制作，不启动训练、不要求新跑现有模型消融、不自动更改产品默认参数。教师可采用更强模型、人工或程序化生成；所有声称正确的轨迹仍须在对应工具环境重放验证，教师自评不能代替验收。

## 2. 数量与覆盖

总量 700 = 630 训练 + 70 验证。36 个种子都必须各有一条通过验收的正确轨迹锚点，锚点计入训练和总量；另造 664 个新实例。

| 场景 | 种子数 | 每种子总记录 | 总量 | 训练 | 验证 |
|---|---:|---:|---:|---:|---:|
| config | 4 | 20 | 80 | 72 | 8 |
| code | 4 | 20 | 80 | 72 | 8 |
| docs | 4 | 20 | 80 | 72 | 8 |
| filesystem | 4 | 20 | 80 | 72 | 8 |
| hybrid | 4 | 20 | 80 | 72 | 8 |
| logs | 4 | 20 | 80 | 72 | 8 |
| script | 4 | 20 | 80 | 72 | 8 |
| tabular | 4 | 20 | 80 | 72 | 8 |
| web | 4 | 15 | 60 | 54 | 6 |
| 合计 | 36 | — | 700 | 630 | 70 |

此为小规模首版的覆盖预算，不是验证过的最优配方。工作区/联合任务 640，纯网页补充 60；逐题训练/验证分配见 plan.json。质量不达标就报缺口，不能只换字符串、复制轨迹或放宽验收来凑数。

同一道题的重复运行、修复版、语言翻译、不同 prefill 和不同 ctx 渲染属于同一任务来源，不增加“独立题数”。只有环境、约束或求解过程存在有意义变化的新实例才计数。

## 3. 种子归档与使用规则

- seeds/original/ 保留原始字节；case.json 包含用户任务与文件/网页夹具，NOTES.md 和 verify.py 是教师/验收侧参考。seeds/cases.json 是归档运行中的规范化 Case 快照；缺省空 expect 等序列化差异不表示题目变更。
- 原题可以在去除元数据/答案泄漏后渲染成训练锚点。原 36 题之后只能作开发回归，不再报告为未见题泛化。
- WORKBANK-CANARY、原题 ID、标签、答案字段、参考解法文字、verify.py 和隐藏测试夹具不进入模型 prompt/监督文本。正常任务所需的工作区文件照常可见；工具回执必须由正常工具执行取得。
- 发现原题歧义、错误答案或不合理参考步骤时，保存 issues 记录和修订后的 derived case；不可回写冻结原件，也不可为了让模型答案通过而改 oracle。锚点若必须修订，应记录 parent_seed_id、原/新哈希、理由及验证证据。
- ref_calls 只是参考标注，不强制追求某条唯一最短轨迹。正确性、有效证据和合理停止优先；禁止无意义循环。

## 4. 先制作正确锚点，再扩题

### M1：36 条正确轨迹

对每题先建立独立的答案/产物 oracle，再编排合理工具路径并实际执行。缺省顺利路径应完成原始任务的全部验收，包括文件保持不变、脚本输出与隐藏夹具等；不能用一句 DONE 代替交付。

已有失败提供以下重点，但每题仍按真实要求求解：

- code-0002：按日志中的测试记录正确计数，一次必要计算后停止，避免不断追加 +1。
- fs-0004：文件名发现与文件内容搜索分开；空内容搜索不等于文件不存在。
- tab-0003：分清数据行数与唯一订单数，按任务定义的唯一键去重，计算忠实于输入。
- cfg-0001 / doc-0003：证据充分后分别给纯值或指定 UNKNOWN。
- cfg-0003：读取并应用优先级/启用条件，不能只看到 true 就答 yes。
- doc-0001 / scr-0002 等：真实产物与脚本语义正确，包括字段名、排序、过滤和保护范围。
- 本地/网页任务成对覆盖，不能教成“任何题都先本地”或“任何题都先网页”。

### M2：72 条新实例小批制作

每种子先做两个有实质结构变化的新实例，共 72 条。与 36 条锚点合计 108 条，全部属于最终 700 配额的一部分。先冻结分支和 split，再生成；不得先看验证集得分再调其难度/答案。

这批用于验证生成器、oracle、执行回放、wire、loss mask 和长度流水线。任何系统性错误修完并回归后，才能扩到剩余 592 条。

### M3：补齐至 700 条

按已验证生成分支扩展，逐条执行并验收，拒绝样本进入 rejected.jsonl，记录首因与全部原因。不得只保存成功样本、丢失生成总数与失败漏斗。

## 5. 扩题必须变化什么

每条新实例至少改变一个影响求解的结构因素；单纯换公司名、路径名、日期字面量或答案数字不够。每种子除锚点外至少设计三种生成分支，并记录分支定义与哈希。

| 场景 | 可用结构轴 |
|---|---|
| 配置 | 默认/环境/租户覆盖层级，启用条件，继承，修改目标与保护文件 |
| 代码 | 定义与调用区分，注释/字符串干扰，跨文件引用，精确行号与计数口径 |
| 文档 | 生效/失效日期，例外规则，多文档合并，保持原文的提取，确实缺少信息 |
| 文件 | 目录层级，名称与内容区分，同名不同内容/不同名同内容，大小/类型统计 |
| 表格 | 唯一键，重复行，筛选条件，单位，退款/冲销，跨表关联 |
| 日志 | 时间窗口边界、级别、轮转文件、事件/行数口径、重复事件 |
| 脚本 | 输入列与格式、排序、边界条件、相对路径、真实修改、输出/隐藏样例验收 |
| 联合/网页 | 正确来源、无关页面、版本差异、本地金额与外部规则组合、缺失证据 |

按实际工具能力设计题目；不要为了某条示范凭空增加工具、虚构批量 API 或假设 search_text 会搜文件名。

正常路径与恢复路径均覆盖。每个种子至少两个训练变体体现有依据的恢复/澄清/合理停止分支；若该任务确实没有自然的失败恢复场景，可以采用来源不足/信息完整的对照并写明理由，不能人为强塞错误。空结果只表示当前方法和范围下没有结果；该停止还是换方法须由任务与证据决定。

## 6. 轨迹、工具与数据结构

使用 work-v1 的真实工具行为和 file-tools=lines；工具校验以当前 Go 实现为准。冻结工具实现/目录版本，期间有 bug 修复则重放受影响样本并更新版本，不能混用未经标注的回执。

- 真实执行 teacher 选择的调用，完整保存 name、arguments、result/error 和先后顺序。工具回执不能由教师编造或手填预期答案冒充。
- 网页任务使用确定性的 web_fixture 和受控回放；隐藏验收文件只由验收器挂载。不要依赖实时网站内容或泄露教师私有上下文。
- 输出正确的普通 final 或当前 wire 支持的 no_tool；遵守纯值、固定标记、JSON 或自然语言契约，不一律复述中间数字。
- 默认一条轨迹一次只发一个可执行调用；不新增现有 wire 不支持的并行包裹。
- 正向 SFT 只监督正确动作/回答。需要从错误上下文恢复的样本，将错误前缀作为明确 mask 掉的上下文，记录 recovery_prefix 边界；不要把故意错误动作同时监督成正确目标。工具因环境返回的真实无结果/不存在等可以作为正常恢复上下文。

三层分离：

1. raw：教师候选、初始 fixture、实际执行日志，不覆盖原始记录。
2. normalized：wire 无关的任务和 messages、工具定义、oracle、来源、split、审查状态。
3. rendered：确定性渲染的 text、loss_spans、meta；改 wire 只重渲染，不重新猜工具回执。

每条 normalized 至少包含以下字段（具体 schema 由实现阶段冻结）：

| 字段 | 要求 |
|---|---|
| id / parent_seed_id / scenario | 新数据 ID 与种子溯源，ID 不渲染到任务文本 |
| is_seed_anchor / generator_branch / instance_group_id | 锚点标记、结构生成分支及所有近似版本共用的分组 ID |
| split / language / behavior_tags | train 或 validation，任务语言，多标签行为描述 |
| task / initial_files / web_fixture | 用户看到的任务和初始环境；验收侧隐藏资料独立存储 |
| tools / tool_catalog_hash / tool_impl_revision | 工具定义、目录与实现版本 |
| messages / execution_trace_ref | 正确轨迹及真实执行证据；工具调用与回执一一对应 |
| expected / verification / artifact_hashes | 独立 oracle、执行结果、文件和脚本验收记录 |
| teacher / generator_version / random_seed | 制作方式与可复现参数；API 密钥不落盘 |
| review_status / reviewer / reviewed_at | 审查状态，不能仅以教师自评标 approved |
| recovery_prefix / supervised_turns | 错误上下文和监督边界；无恢复前缀时显式为空 |

训练输出不附隐藏思维链。制作人员的分析和参考解法只存教师侧，不当用户可见回答监督。

## 7. wire、长度及与 v1 的关系

主轨道采用 xml-v1+align-qwen36+no-tool+bare+one-stage，thinking off / prefill=none，ctx4096。工具输入输出均按真实协议渲染并通过 Harness parser，无需 repair。

若另外输出 think-fast 对照，必须同 ID、同 split、同语义内容，仅改变明确的 prefill/history 配置；prefill 的 <think></think> 属于输入侧且 mask。对照渲染不新增样本计数，不将它与加载 state 混称一个干预。

使用 RWKV 真实词表计数，词表 SHA 固定见 plan.json。完整 text 包含目录、历史、所有工具回执和最终监督目标，长度必须 ≤4096；禁止截掉目标答案/关键回执后冒充合格。过长样本须重设计高效路径或任务规模并重验；保留原候选及淘汰原因。

v1 的 raw/normalized/rendered 分层、真实 token 计数和 mask 校验可复用。**不要直接运行带旧配额的 v1 render.py 覆盖成品，也不沿用每 schema 最多 20 条的来源均衡规则**：本轮有意训练固定 work-v1 工具，沿用该上限会导致错误淘汰。

本轮与旧日常/客服语料分开交付，不自动拼接，不默认沿用 no-call 600 条或其比例。语言先沿用种子任务；若生成中文版本，按真实新实例制作，翻译/同实例改写留在同一 split，不能翻译后当独立新题凑数。交付时报告语言分布。

## 8. split 与交付

700 条先分配到训练/验证生成分支，再生成内容。一个实例的错误修复、重写、翻译、none/fast、不同长度渲染必须同 split。train/validation 不得只靠随机打散换名后的近重复样本。

70 条验证属于“同一种子家族的新结构/新实例验证”，不能宣传为独立跨家族泛化集。验证分支由独立约束/规则组合定义，生成器分支清单在生成前冻结；不可为了成绩有意让验证集更容易。原 36 题作为训练锚点后仅作开发回归。

交付清单：

- normalized/all.jsonl（700）、train.jsonl（630）、validation.jsonl（70）。
- rendered/none-ctx4096/{train,validation}.jsonl，含 text/loss_spans/meta；若有 fast 对照另列。
- 原始执行证据、oracle/验收器、生成器及版本、split-manifest.json、hashes.json。
- verification/results.jsonl：700 条逐题检查，不能只有总通过率。
- verification/acceptance-report.md/json：覆盖矩阵、token 分布、去重/泄漏检查、缺口、失败漏斗、审查记录。
- rejected.jsonl 与 issue 清单；未达 700 必须报实际数量，状态为未完成。

最终验收标准见 ACCEPTANCE.md。数据制作验收与训练收益验收分开：本需求单不以某个模型的通过率提升作为“语料已正确”的替代证据。
