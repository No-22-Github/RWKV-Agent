# 700 条语料验收要求

> **2026-09-20 用户口径修订**：本次交付允许已审查的少量 train 内结构近重复，不要求为凑结构差异重写。具体 13 条及授权见 [保留政策](verification/phase3-retention-policy.json)。下文严格结构新颖性要求对该清单作显式例外；正确性、真实回放、契约、mask/token、精确内容去重及跨 split 隔离门槛继续执行。交付数量 700 指记录数，不宣称 700 个结构独立任务。

适用版本：workspace-agent-700-v0。验收对象是任务、正确轨迹、真实回执和最终训练文本，不是题目数量或教师自称完成。本轮归档检查只代表准备工作通过；700 条语料须完成下列独立验收。

- 每个原题目录完整包含 case.json、NOTES.md、verify.py；108 个原文件逐字节复制，SHA-256 与来源一致。
- 保留初始 files、网页夹具、每轮 prompt/expect、全局文件/脚本验收与隐藏夹具。种子原件与冻结运行 Case 语义一致；缺省空对象等序列化差异允许。
- 来源、归档位置、逐文件哈希可追溯，所有链接指向本轮正确位置。
- plan.json 数量守恒：总量 700、训练 630、验证 70；逐种子/场景配额加和相等。
- 当前已完成正确轨迹明确为 0，不将原题或失败回放标记成训练成品。

执行 tooling/verify_archive.py，结果存 verification/archive-check.json。它只检查归档与计划，不执行模型，也不证明参考轨迹正确。

## B. 任务与 oracle：700/700

| 检查 | 通过要求 | 判退例子 |
|---|---|---|
| 任务可判定 | 在给定 fixture/工具能力下有确定答案或明确的合理弃答/澄清条件 | 隐藏必要信息却要求精确答案 |
| fixture 完整 | 文件、网页响应、日期基准、编码和环境依赖齐全，可重建 | 需要联网猜最新网页或用制作者机器上的额外文件 |
| 独立 oracle | 正确值/预期产物由程序或人工独立核验，记录口径 | 直接把教师最终回答抄为 expected |
| 语义口径 | 行数/唯一实体、时间边界、单位、优先级/规则例外写清或可由可见材料确定 | 把 23 行不加解释地认定为 19 个订单 |
| 结构新颖性 | 新实例改变约束、证据布局、规则或求解过程，记录分支 | 只改公司名和答案数字、复制同条轨迹 |
| 工具可用性 | 任务可用现有工具完成，schema 与实现一致 | 示范工具目录中不存在的操作 |

原始 verify.py 可能只计算参考值，不能单独当完整的任务验收器。文件修改/脚本任务必须执行 CaseExpect.Files/Run 或同等强度的独立验收。任务歧义或旧判据不合理需先登记和版本化修订，不为现有模型输出追改答案。

## C. 正确轨迹与回放：700/700

每条从干净环境重放全部工具调用，记录并检查：

1. 调用符合所冻结的 name/arguments/schema；工具执行顺序和结果可追溯。
2. 回执来自真实工具执行。规范化允许移除时间戳/临时绝对路径等非语义噪声，但保留原始回执，并记录 normalization 规则。
3. 后续参数和答案忠实于回执；无编造数字、来源、文件存在性或“已经完成”。
4. 所有目标验收通过：最终内容、输出契约、必需行为（若适用）、文件最终态、未授权/不应改变文件的字节保持、脚本 stdout 和隐藏用例。
5. 有限且合理的路径：无无意义重复/递增加一循环；重复调用有环境变化、分页或其他明确必要理由。正确但明显冗余的轨迹应改写后重放。
6. 错误恢复样本区分无匹配、文件不存在、权限、参数错误和外部故障；恢复动作由证据支持，不固定教“空结果就一定继续调”。
7. 正确的最终答复可来自 decision 阶段；不要求字面必须进入 answer stage，也不把无工具调用一律判坏。
8. 原 36 条锚点必须先逐条重放、审查通过；全部通过前不得以扩题数量掩盖错误模板。

所有 700 条至少重放一次。36 锚点、70 验证以及涉及随机/时间/网页 normalization 的样本额外从干净环境再回放一次；两次差异必须解释并消除非预期差异。这里是确定性工具回放，不要求 G1K 自行重新生成相同动作。

## D. 内容、语言与格式分开

- 对纯值/固定格式任务继续要求精确终答。内容正确但啰嗦，不作为该任务的合格监督答案。
- 对澄清/拒绝/错误恢复，核验是否问对缺失信息、是否如实描述状态；不能仅用含 path / 路径 / unavailable 等词判语义正确。
- 语言遵循单列。标识符、文件名、数字单位、实体及原文提取条件仍精确检查。
- 同时记录 content_pass、contract_pass、artifact_pass（不适用为 null），最终 accepted 只有全部适用项通过才为 true。
- 不改原 Workbank frozen scorer。派生题如有新判据，明确 scorer_version，正例、语义近似的错误例和中英等价例应覆盖；新/旧分数不混为同一列。
- “复述所有回执”不是通用要求；中间正确性用回放/oracle验证，用户要纯值时最终只给纯值。

## E. 数据结构、协议、mask 与长度：700/700

| 项目 | 硬性要求 |
|---|---|
| 来源 | id、parent_seed_id、branch、instance_group_id、split、teacher/generator 版本齐全 |
| 结构 | normalized 可重建完整任务与轨迹；工具调用与回执一一对应，无悬空结果 |
| parser | 所有受监督调用和 final 经当前 Harness 正常解析；0 repair、0 混合说明/调用、0 伪造不支持包裹 |
| mask | loss_spans 仅覆盖计划监督的正确 assistant 输出；system/user/tool、prefill 和错误 recovery prefix 均不受监督 |
| 特殊 token | 使用实际 RWKV tokenizer；不得用字符数/fixture bytes/词数估算 token |
| 长度 | 主轨道每条完整 rendered text ≤4096，含目录、全部历史和最终目标 |
| 截断 | 不允许静默截掉工具回执、答案、JSON 尾部或最后监督 token；过长重设计/拒绝 |
| 渲染一致性 | 同输入+配置重渲染 text/mask/hash 一致；none/fast 如双轨应同 ID/split，不重复计数 |
| 可重现 | 保存词表 SHA、renderer/parser 版本、工具目录与实现版本、所有文件 SHA |

一次性验证 parser/mask/长度检查器的负例：坏 JSON、说明文字混入调用、错误字段、tool 回执被监督、prefill 被监督、目标超长/截断、无工具回执。负例必须被对应检查拒绝，不能只看到正例全绿。

## F. 去重、split 和输入隔离

- 700 个唯一 id；630 train 与 70 validation，集合无交集并覆盖 all。
- 36 锚点均为 train；同实例修复、改写、翻译、渲染变体统一 instance_group_id 且同 split。
- split 先于生成；验证分支定义和版本已冻结。不得依据训练后表现挑选验证题。
- 全量精确哈希去重，并对去标识符/数字后的任务结构和轨迹结构做近重复候选筛查；跨 split 候选人工确认，未解决的冲突为零。不能宣称自动近重复阈值等于语义无泄漏。
- WORKBANK-CANARY、NOTES、expected/verify 内容、隐藏 fixture、制作元数据和 API 密钥不得出现在模型输入/监督文本。正常可见文件中的事实可以经真实工具进入回执。
- 原题在种子归档中保留 canary/答案等元数据不算泄漏；隔离检查的对象是实际 rendered 模型文本及可见 fixture。
- 70 条验证报告为同种子家族新变体，不能宣称未见家族的独立泛化能力。

- 指定脚本从保存的 raw/normalized 重建 rendered，哈希可复现；数据、验收脚本和报告齐全。

acceptance-report 至少包含：请求目标/实际产量/缺口、9 场景与36种子配额、行为标签和语言分布、token p50/p90/p99/max、工具调用步数/回放错误、验证维度统计、人工样本清单、精确/近重复结果、split/版本/哈希、已知局限。
