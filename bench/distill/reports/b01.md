## 7. 本批发现（三条已按决定处置 + 一条留档）

### 7.1 超能力拒绝题只给出裸 `UNKNOWN` —— 已在规格层修

**根因在规格，不在判据**：这类题的题面以 `… If you cannot determine the answer, reply exactly UNKNOWN.` 收尾，等于替模型把「做不到」写成了弃权；判据（文档 §2.5 的规范词表）当时也认 `UNKNOWN`。b01 的 19 道拒绝题里老师 19/19 答裸 `UNKNOWN`。

处置：
1. 文档新增 **§4.3.1**：`beyond_capability` 与一切带 `TR-NOCAP` 的题**不带 UNKNOWN 契约**，判据用拒绝语并加 `output_excludes: ["UNKNOWN"]`，保留 `forbidden_tools`，**允许先查工作区再拒绝**（不强制零调用）；§2.5 的示例 expect 同步改。
2. lint 实现（仅在 `--canary-prefix` 不是 `WORKBANK-CANARY` 时生效，测试集冻结、不误报）：报 `answer_contract.refusal` 与 `expect.refusal`，三条负向/正向测试齐备，workbank 回归仍 148 题 0 违规。
3. 本批 **28 行**裸 `UNKNOWN` 行按 `reason: "nocap-bare-unknown"` 写进 `exclude.jsonl`（筛选条件：`case_tags` 含 `TR-NOCAP` 或 `task_type == beyond_capability`，且 `traj.final_kind == "unknown"`）。
4. 16 道拒绝题（`nt-5093..5102`、`cfg-5006/7/8`、`fs-5006/7/8`）按新规格改题、version+1，**进 b02 重跑老师**。

剔除后数据集里 **`kind == refuse` 的行为 0 行**——这正是要在 b02 补回来的。

### 7.2 多轮题拿不到零调用 `clarify` —— 已改口径（不改题）

先查再问是好行为：查了工作区、发现两个 Ridgeway 再问「你指哪个」比不看就问更有依据。处置：

1. §4.4.2 规则 3 去掉 `zero_call` 条件，改为「`traps` 含 `TR-AMBIG` 且 `turn < turns_total`」。本批重渲染后 **25 行（18 道多轮题的第 1 轮）全部为 `clarify`**，text 逐行不变。
2. D 类配额按 `kind == clarify` 统计，不再要求第 1 轮零调用。
3. 零调用反问只在「工作区里没有可查的东西」时才自然成立——b02/b03 的 notool `ambiguous_request` 按这个设计（缺的是只有用户知道的信息：哪个客户、哪个月、哪个单位），每批 6–8 道；hybrid 的多轮题不要求零调用。

### 7.3 超 4096 token —— 已收紧预算

`allocation-v1` §5 改为：E 类 ≤ 3KB、G 类 ≤ 6KB、其余 ≤ 4KB、多轮两轮合计 ≤ 4KB、web 页面每页 ≤ 2KB；并加批次指标「超长剔除行 ≤ 2% 算正常，超过就下一批再收紧，不放宽 4096」。b01 的 4 行（1.1%）按原规则剔除，不重跑。

### 7.4 留档：scorer 的数值判据不接受 `47.2%`（不改，待单独决定）

`tab-5018` 的处置（题面写明「不带 % 号」）可接受，但它暴露 scorer 的一个缺口：数值判据接受 `576 MB`（数字 + 空格 + 单位，`isUnitSuffix` 还明确允许 `%`），却不接受紧贴的 `47.2%`——同一类问题在 workbank 反例 **X-005** 里有记载。**本次不改 scorer**（改了要升 scorer 版本，会影响测试集分数的可比性），先留档；在那之前，百分比题的题面统一写明「不带 % 号」。
