## 5. 本批遇到的三件事

### 5.1 decontam 的 names 维度命中了样板标识符（已改题）

`nt-5159/5160/5161` 三题被 names 维度判为与测试题 `nt-0002` 相似 0.333。查下来命中的是 **`sign-off`** 这一个连字符标识符——`nt-0002` 的题面里有它，我们三题的 README 里也写了「the sign-off list」。这三题名字很少（一个 `.txt` 登记册 + README），Jaccard 对单个重合就极其敏感。
按规程「命中就重写、不得调阈值」：把三题 README 里的 `sign-off` 改成 `approval`，names 归零 ✓。**给后续批次的经验**：短 fixture 的题要避免复用测试题里出现过的连字符/点号标识符。

### 5.2 未知字段让老师跑三轮当场全灭（已加闸门）

第一次 `teacher-k0/k1/k2` 全部秒退：`load Agent eval cases: decode … unknown field "answer_once"` —— `tab-5027` 的 case.json 带了个自写字段，而 agent-eval 的 loader 用 `DisallowUnknownFields` **拒绝整个 bank**。lint（只看 tag 词表）与 verify（只跑脚本）都看不见它。
- 修掉字段（version+1），全库重新加载通过；
- 新增 **`rwkv-lab corpus loadcheck --cases <dir>`**（直接调与 agent-eval 同一个 `eval.LoadCasesDir`，422 题约 5 秒），带测试，写进规格 §3 S2 作为 S4 前的最后一道闸门；
- 全库审计：只有这一个未知字段（顶层/turn/expect 三层都比对过 schema）。

### 5.3 `corpus pack --exclude` 需要按批次区分（已修工具）

b01 有 28 行拒绝题数据按 `reason: "nocap-bare-unknown"` 被剔除，条目里带 `batch: "b01"`；本批那 16 道题改写后重新出题、**case_id 不变**，于是这些旧条目把本批**新跑出来的合格拒绝行**也一起剔掉了（`refuse` 一度只剩 2 行）。
修法：`--exclude` 的条目按 `batch` 与行的 `meta.source`（去掉 `distill-` 前缀）匹配；条目不带 `batch` 时仍作用于所有行（手写剔除的语义不变）。加测试，并验证 b01 重打包行数不变、b02 的 `refuse` 从 2 回到 54。
