未达标项的原因：

- **首轮零调用 11.9%**：b10b/b10d/b10e 三批 778 行全部要调工具，首轮分母增加；全部行的零调用 549 行含后续轮次，不能替代首轮 361 行。仅新增单轮零调用题、其余数据不变时，达到首轮 22% 至少需 395 行：`(361 + 395) / (3040 + 395) = 22.0%`。补 250 行只到首轮 18.6%（全部行 22.6%）。后续还要加入 b12 时必须按最终配额重算，并同时补多轮与小清单，不能把 395 当作最终补题数。
- **首动作 list_files 55.8%**：题面给了路径也先列目录，本次只统计、没有按此过滤。按修正后的计数，即使删掉全部 353 个「给路径仍先 list_files」首轮样本，首轮工具样本比例仍是 `(1495 - 353) / (2679 - 353) = 49.1%`，达不到 40%。这不是实际路径级删行预测（删路径会连带其他轮次）；应替换冗余探索轨迹、补充直接打开目标的样本，并在过滤后重算，不能声称删约 340 行即可达标。
- **data_query 6.2%**：M6 日期混写题里 data_query 没法归一日期、单位混排题老师更愿意整读后换算，这两类最后都去掉了 required data_query（见 b10d 报告）。这既是工具能力边界，也是训练行为目标的缺口：当前 b10d 251 行中 150 行用 read_file 读取至少 80 行的表或日志，其中 27 行没有 data_query。应区分确需完整读取与可用工具聚合的题，不能仅因答案正确就认为 M6 行为目标达成。
- **多轮 14.1%**：多轮行几乎都来自 M3（b10a），其余新题类都是单轮。

## 6. 这轮放量学到的（给后续批次）

1. **案级 `max_calls.read_file` 是最大的误杀源**：b10c、b10d 两批首轮大量 0/3 都因为「先读 README」或「连接题要读两三份文件」超限，且 summary 不写案级失败原因。出题说明应改为不设或只针对大表。
2. **排除项会误杀正确的解释**：M7「第三方页面的旧值 X 已过时」、不写类「所以没有回复 DONE」都被排除项判挂。排除项只该排除「把错值当答案」的说法，旧值类题靠必含正确值就够了。
3. **题目里的日期要和「今天」（2026-09-16）对齐**：b10e 有 8 题新值写「自 10 月 1 日起」，老师说「还没生效」反而是对的。
4. **计数题用 token 判据**：中英文计数的说法（「2.」「3 Ale beers」「28 个」）词表永远收不全；英文改 token 后要给 verify 加 fixture sha256，否则破坏测试测不出来。
5. **老师的固定毛病，用程序扫**：英文题用中文 / 德文 / 法文回答（`local/runs/distill/v141/qa/lang_scan.py`）；用户没要求却在终答里提 DONE（suffix 口径外溢）；终答里自我更正、凭空数字只能靠逐条读。

## 7. 2026-10-11 独立复核：报告与交付边界

1. **统计漏读已修正**：`v14_composition.py` 原来只通过 live case.json 找题面，80 条 base700 全部返回空字符串。现在对缺少 case.json 的行从第一条监督输出之前取真实用户题面；原 UNKNOWN 70 行修正为 133 行，给路径首调 list_files 从 342/1021 修正为 353/1050。中文 1460/3288 不变（base700 全为英文）。终答检查同时剥掉旧行已监督的 `\n\nUser:` 后缀，避免裸终答扫描被后缀干扰。
2. **新增闭环达标，存量仍有反例**：按实际调用参数核对每次写后是否回读同一文件，新增 b10-pilot、b10a–e 的 298 行确实全部满足；统计脚本原来的「最后一次写后有任意读工具」只是较弱检查。全量仍有 108 行至少一次写后未回读同一文件，来自 b05、base700、b06、b07。新增达标不等于全量已统一教会闭环行为。
3. **DONE 格式漏检**：保留的 `cfg-8633--p1`、`cfg-8662--p1` 把 DONE 接在说明句后，`hyb-8608--p1` 以 `DONE — …` 开头，均违反新增行「DONE 独占最后一行」。现有 contains 判据能通过；应在 S5 增加明确的终答格式检查。否定句中的「未写 DONE」不应直接当作成功标记或自动删掉。
4. **最终训练包未统一**：这 3288 行的来源中 1192 条旧行已经带末尾 `\n\nUser:`，2096 条新行未带。直接混用会造成结束监督不一致；对全量再次调用非幂等的 `build_v13_suffix.py` 又会给旧行追加第二次。最终打包须保证每行恰好一个结束后缀，再 split / pack / segments / segcheck，并披露 train、validation、manifest 和 SHA256；本报告的 8121 token 是当前来源集合值。
5. **验证隔离与来源污染**：如果原样沿用 `split_v13.py` 的 case ID 哈希，候选集合会是 train 3180 / validation 108，有 19 个 family 跨两侧。它隔离同题路径，但不保证 family 独立；这是分割模拟，尚不是最终交付分割。80 条 base700 均标 `seeded_from_test=true`，训练后的 workbank 结论须使用明确剔除这些来源的干净考卷，不能宣称全量来自独立新题。

本轮只修报告与统计脚本，没有改题目、老师路径、exclude 或训练数据；上述质量问题仍待处置。题目 verify 与 pack / segcheck 通过不代表这些行为问题已解决。
