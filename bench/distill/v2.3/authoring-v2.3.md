## 0. 这一轮要教什么

v2.3 的新题对准 G1L 基模和 v2.2 训练后的几类死因：

- 信息不全时直接动手改文件（应该先追问）；
- 3 轮以上的多轮对话全错；
- 改文件改错了还说"已完成"；
- 目录里没有合适的工具时编造工具名；
- 题面带公司/产品名就先上网（v2.2 的 b22a 教过头了）；
- 答案在第一屏之后却只读第一屏就作答。

每批都要有**对照组**，题面风格、长度、语言和正向组接近，只有"该不该"的关键信息不同。

## 2. 全批通用要求（v2.3 新增）

1. **英文 ≥ 50%**（每个子类都要做到）。考卷中英各半，现有训练包中文 60%。英文题面要像真实用户写的英文，不要从中文直译。
2. **网页 fixture 不用 `.example` 域名**。老师看到 `.example` 会说"这是模拟数据"或反复去找"真官网"，这类轨迹 v2.2 剔掉了 52 题。用看起来真实、但虚构的域名（如 `docs.lumenstack.io`、`www.hengtai-logistics.cn`），不要用真实公司的域名。
3. **短路径优先**：参考通过路径控制在 1–6 次调用（b23d 按轮计）。题目不要逼模型反复试错；需要大量 grep/awk 换写法才能做出来的题不要出。
4. **多轮（≥ 2 个用户轮）≥ 30%**（b23d 全部是多轮；b23g 可降到 15%）。L0 ≤ 20%。
5. 子类数量按 §1 的表，偏差不超过 ±3 题。

## 3. 各批次的要求

### b23b 本地优先对照（80）

背景：v2.2 的 b22a 题面常带公司或产品名，教出了"看到实体名就先上网"，结果本地题第一步 web_search 从 2 次涨到 17–19 次。这批把它拉回来。

- **B1（40）**：题面带公司名、产品名、库名或政策名，问的是**我们自己的**数据或约定（"我们和华达的合同里写的付款期限""our deployment guide's timeout for the Lumen gateway"），答案在工作区文件里。工作区里要有明显线索（文件名、题面里的"我们的/our/内部"），但不要每题都用同一个词。
  - 判据：`forbidden_tools: ["web_search", "web_fetch"]`；`output_contains` 放文件里的值。
  - 一半题在 `web_fixture` 放一个**数值不同**的同名网页（官网公开价、旧版文档），`output_excludes` 放网页里的值。
- **B2（20）**：用户要外部信息，网页搜不到（fixture 不匹配）或网址打不开，但工作区里有一份可用的本地副本或旧记录。通过路径：上网 1–2 次失败 → 回本地找 → 作答并说明来源是本地文件、可能不是最新。另有一部分题本地也没有，就如实说查不到，不编。
  - 判据：`max_calls: {"web_search": 2, "web_fetch": 2}`；`output_contains` 放本地值；查不到类用 `output_contains_any` 收"没找到/查不到/无法确认/couldn't find/not available"一类说法（中英文收全，至少五种说法自测）。
- **B0 对照（20）**：题面风格同 B1（同样带实体名），但问的是外部、会变化的信息（官网现行价格、最新版本号、公开公告日期），工作区里没有或只有过期的旧值。
  - 判据：`required_tools: ["web_search"]`；`output_contains` 放网页值；有旧值的题 `output_excludes` 放本地旧值。
- B1 与 B0 要成对出：同一个实体在两道题里分别问"我们的约定"和"公开的现行信息"，放在不同题族里。

### b23c 信息不全先追问（70）

背景：现有训练包里"追问"只有 7 题。G1L 遇到信息不全时会直接改文件。

- **C1（50）**：用户要求改动或给结论，但缺一个**无法从工作区推断**的关键信息，例如：
  - 工作区里有两三个都对得上的候选（`config/staging.yaml` 和 `config/prod.yaml` 都有这个键，用户只说"把超时改成 30"）；
  - 缺一个只有用户知道的值（"把负责人改成新来的同事"，工作区里没有新同事的名字）；
  - 要求本身互相矛盾（"按上周的模板写，但上周有两个模板"）。
  - 通过路径：读文件确认歧义（可以调只读工具）→ 不写任何文件 → 终答用一个具体问题问清楚（列出候选）。
  - 判据：`forbidden_tools` 放所有写入工具（`write_file`、`replace_lines`、`append_file`）；涉及的文件 `expect.files: {"<路径>": {"unchanged": true}}`；`output_contains_any` 收追问的说法，并且 `output_contains` 至少放一个候选的名字（证明模型看到了歧义）。
  - **其中 20 题做成两轮**：第一轮追问，第二轮用户回答（"改 staging 那个"），然后模型执行。第二轮用 `expect.files` 判结果。
  - 歧义必须真实：正常路径一定会读到冲突的那几个文件；不要让题目看起来像"故意找茬"。
- **C0 对照（20）**：题面风格和 C1 一样，但信息足够（只有一个候选，或用户说清了是哪个）。通过路径：直接改，终答说明改了什么。
  - 判据：`expect.files` 判结果；`output_excludes` 放"请问您指的是/which one do you mean"一类问句。
- 这批由 DeepSeek 当老师，题目不要依赖千问特有的行为。

### b23d 3–4 个用户轮（60）

背景：考卷里 16 道 3 轮以上的题 G1L 两遍全错，训练包里只有 10 题。

- 每题 3 轮（D1）或 4 轮（D2）。轮次之间要真的有依赖：后面的轮次用到前面读到的事实、改过的文件，或者用户**中途纠正**前面的要求（"刚才那个改错了，应该是 prod 不是 staging"）。
- 要有的模式（各占一部分）：连续改同一个文件；先查、再改、再汇总；中途纠正并撤销；最后一轮让模型总结前面做过的所有改动。
- 每一轮都要有判据（按轮写 `expect`）。最后一轮的判据必须用到第一轮的事实。
- 每轮的参考路径 ≤ 4 次调用，整题 ≤ 12 次。总轨迹控制在 8K token 以内。

### b23e 改完核验、改不成如实说（60）

背景：G1L 写类题里 `replace_lines` 的区间和内容对不上，改错了仍说"Done"。

- **E1（25）**：要改的是多行块或会影响行号的改动（插入、删除多行、连续改两处）。通过路径：读 → 改 → 回读改动处附近确认 → 作答。
  - 判据：`expect.files` 判最终内容（要有能区分"改对了"和"改错一行"的检查）；`required_tools` 含 `read_file`。
- **E2（20）**：改动做不成或做不对：要改的键不存在、文件里有两处一样的文本不确定改哪处、用户给的行号和内容对不上、文件是只读或二进制格式。通过路径：发现问题 → 不乱改 → 如实说明原因和建议。
  - 判据：相关文件 `unchanged`；`output_contains_any` 收如实说明的说法；`output_excludes` 放"已完成/已修改/Done/updated successfully"一类说法（注意别误杀"未完成"）。
- **E0 对照（15）**：在文件末尾追加一行、新建一个小文件这类简单写入，不需要回读。判据只看文件结果，`max_calls` 限制总调用数（例如 ≤ 3），防止过度核验。

### b23f 工具不在目录（50）

背景：G1L 有 11%–12% 的失败是编造目录里没有的工具名，含这类调用的题几乎全错。

- 用 `tool_policy` 让最合适的工具**不出现在目录里**（例如 `never_offer: ["calculator"]`、`["bash"]`、`["data_query"]`、`["web_search", "web_fetch"]`）。字段写法以 v2.0 出题规格的 `tool_policy` 为准（10-30 更正：字段名是 `never_offer`，不是 `must_not_offer`）。
- **F1（20）**：用现有工具能变通完成（没有 calculator 就用 bash 的 awk 或分步手算；没有 data_query 就用 bash 统计；没有 bash 就 read_file 后手算小数据）。判据只判结果。
- **F2（15）**：确实做不到（没有网页工具却要查实时信息；没有写入工具却要求改文件）。通过路径：不编工具、不假装做了，说明做不到并给出替代（让用户自己查哪里、提供改好的内容让用户粘贴）。
  - 判据：`output_contains_any` 收如实说明；`output_excludes` 放编造结果的典型值。
- **F0 对照（15）**：同类任务，合适的工具在目录里，正常调用。
- 交付前用 gate 实际看一下：模型调用不存在的工具名时 harness 怎么返回、scorer 怎么判。如果 scorer 没有专门判"调了不存在的工具"，在报告里写明，由主 Agent 处理。

### b23g 第一屏之外（40）

背景：agent-tool-v3.x 的 read_file 不给范围时只返回一屏（最多 200 行或 12KB），结果里有 `total_lines` 和续读提示。v2.2 训练后出现了只读第一屏就作答的错误。

- **G1（30）**：文件 300–1500 行，答案在第 200 行之后；第一屏里放一个**相似但不对**的值（旧版本号、另一个环境的配置、草稿里的数字），`output_excludes` 放它。通过路径：read_file → 看到没读完 → `start_line` 跳读或 search_text 定位 → 作答。
- **G0 对照（10）**：文件同样较长，但答案就在第一屏、而且题面问的就是开头部分（"文件头写的版本"）。判据加 `max_calls: {"read_file": 1}`，防止无谓翻页。
- fixture 内容要像真实文件（变更记录、长配置、长日志），不要大段重复同一行。
