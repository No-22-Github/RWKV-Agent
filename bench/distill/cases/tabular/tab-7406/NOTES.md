## Traps
- TR-NEARNAME（恢复题，恢复行为是考点）: 题面只说「实际结算给承运方的运费」，表里没有叫「运费」或「配送费」的列，只有一对近名列：运费报价（下单预估）与实付运费（对账实付）。第一次用猜测的列名聚合会收到 `field "运费" is missing` 之类的报错；filter 引用不存在的列则返回 matched_rows 0。模型要从报错或空结果恢复：用不带 operation 的 data_query select 列出真实表头（或用题目预算内最多一次 read_file 看表头），再改用实付运费重查。README 写明实付运费才是对账后要支付的金额。
- 顺手聚合运费报价会得到 3272.76；正确答案是实付运费的合计 3235.75。

## Reference solution
1. 读 README.md：运费报价是下单预估，实付运费是月末对账实际结算、需要支付的金额。
2. 用 data_query 聚合：{{"path":"data/bakery_freight.csv","filter":{{"城市":"成都","配送月份":"2026-09"}},"operation":"sum","field":"实付运费"}}，得 3235.75。（若第一次猜错列名报错：先发一次不带 operation 的 select 看到全部列名，再按本步重查。）
3. 终答只报数字 3235.75。

## Why the answer is unique
decoy 3272.76 是运费报价（下单预估）的合计，但题面问的是实际结算，README 写明实付运费才是对账后要支付的金额，报价只是预估，两列每一行都不相等，按报价作答不成立。其他城市与月份的行被过滤条件排除。答案只有 3235.75。
