## 判据
- D1：每轮 `tools: []` + `expected_number`（in_text，容差 0.01，保留 1 位小数的题 0.05）。通过路径是直接作答。
- D2：只判结果，`expected_number` + 容差（0.01）；`max_calls: {calculator: 2}`。题型：`^`（复利、2^31-1、平方和）、`**`、阶乘/排列、组合数、sin/cos/tan（坡高、楼高、余弦定理、梯子）、log2 取整、ceil（装箱）、立方根、最小公倍数、百分号式子（尾部 `%` 解析失败）。均对照 compute_v3.go/evaluateWith 确认：`^`/`**` 显式报错；`!`、`%` 结尾、`C()`、`sin()`、`ceil()`、`lcm()`、`cbrt()`、`log2()` 都是解析失败或"function not allowed"。
- D0：只判结果，容差 0.006（两位小数）、0.0006（三位）、0.6（取整升数）；不要求具体工具。
- 题面不含"计算器/心算/工具名/awk"（构建时断言）。verify.py 内嵌 compute() 重算全部轮次答案，并断言题面含各输入数字。D2 的参考 awk 命令每次构建在 just-bash 沙箱真跑，输出须含正确答案。

## 走错方向的答法（各子类 2 个）
- D1：(1) 调 calculator "核对" 42/48 → 每轮 `tools: []`，调用即不过；(2) 先 list_files/读 README 再答 → 同样零调用不过。
- D2：(1) 计算器报 `^` 错误后原样重试第三次 → `max_calls.calculator: 2` 不过；(2) 放弃并答"计算器不支持，无法计算" → 没有 expected_number 不过；(3) 报错后凭印象口算出错数（如把 C(12,4) 当成 P(12,4)=11880）→ 数值不符不过。
- D0：(1) 不调工具心算后给出近似值（如 4.58 万月供约数）→ 数值超出 0.006 容差不过；(2) 用单利/少乘一步（如首月本金答成月供）→ 数值不符。

## 已知风险
- D1 与 D0 题面长度有差距（46 对 79 字）：D0 要交代利率、期数等参数，天然更长；模型可能学到"长题面 → 调工具"，这是我们想要的相关性但可能过强，D1 里有 4 道含 3 个以上数字的题（34311、34313、34314、34328）可缓解。
- D2 里部分题（立方根、log2、阶乘）模型可能直接用 pow/ln/连乘在计算器里算对，根本不触发报错，轨迹里就没有"报错→恢复"，只有"一次算对"；这些也算通过，但报错样本会少于 20 条。
- D0 的"该不该用工具"只由结果精度区分（判据不卡工具）：模型凭口算能蒙到的两位小数很少，已用不整的参数降低概率。
- 34358 取 π=3.14159265 取整升数，老师若用 3.14 会差 ~13 升，判不过（题面已给 π）。
- 34351 第二问总利息容差放到 2.0（月供四舍五入后乘 300 期会差 ~1.5 元），所以略宽松。
