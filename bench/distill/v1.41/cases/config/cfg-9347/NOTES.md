## Traps
- TR-DECOY: `# REDIS_URL=old-value` is commented out, so the key is not set. TR-READONLY: deploy/env/test.env is generated by CI (deploy/README.md): neither counted nor edited. SENTRY_DSN is absent from prod, staging and dev, so turn 3 restores the original state of two files.
- Later turns depend on the result of the first one (the answer of turn 1 picks what turn 2 edits), and the last turn changes part of what the previous edit did.

## Reference solution
Turn 1 (answer in the reply):
1. bash: `for e in prod staging dev; do for k in $(cut -d= -f1 deploy/.env.example); do grep -q "^$k=" deploy/env/$e.env || echo "$e $k"; done; done | wc -l`
Turn 2 (edit, reply DONE):
1. bash: `for e in prod staging dev; do for k in $(cut -d= -f1 deploy/.env.example); do grep -q "^$k=" deploy/env/$e.env || echo "$k=CHANGE_ME" >> deploy/env/$e.env; done; done`
2. bash: `tail -n 4 deploy/env/prod.env deploy/env/staging.env deploy/env/dev.env`
Turn 3 (edit, reply DONE):
1. bash: `sed -i '/^SENTRY_DSN=CHANGE_ME$/d' deploy/env/staging.env deploy/env/dev.env`
2. bash: `grep -n SENTRY deploy/env/*.env`

## Why the answer is unique
The first answer is an exact-match aggregate over the files the README describes; every later edit touches only the lines the requests name, in the order they were asked, and everything else stays byte-identical to the fixture (case_expect.files pins every path).

## Five alternative phrasings of the task
1. 对照 .env.example，三个环境一共缺几项？补成 CHANGE_ME，之后 staging 和 dev 的 SENTRY_DSN 再去掉
2. 统计 prod、staging、dev 比示例文件少的配置项总数，追加到文件末尾，再把 SENTRY_DSN 从后两个文件里删除
3. 各环境文件比 .env.example 缺多少个键？用 CHANGE_ME 补齐，然后只保留 prod 的 SENTRY_DSN
4. 数出三个环境缺少的配置项（注释不算），补上占位值，最后撤掉 staging 与 dev 的 SENTRY_DSN
5. How many keys from .env.example are missing across prod, staging and dev? Append them as KEY=CHANGE_ME, then drop SENTRY_DSN from staging and dev again.
