## Traps
- TR-READONLY: settings/test.cfg is regenerated by CI (settings/README.txt).
- TR-DECOY: [pool-replica] looks like [pool]; only the exact [pool] header gets the new line.

## Reference solution
1. bash: `find settings -name '*.cfg' | grep -v test.cfg | xargs sed -i '/^\[pool\]$/a max_idle = 20'`
2. bash: `grep -rn -A1 'pool' settings` to confirm the target files changed and the protected ones did not.
Final answer: DONE (four cfg files gained max_idle = 20 below their [pool] header; test.cfg and the [pool-replica] sections are unchanged).

## Why the answer is unique
Only the files and lines the README allows change, every other byte stays identical.

2. Insert max_idle = 20 immediately under the [pool] section header of the cfg files in settings, then confirm and reply DONE.
3. settings 下的 .cfg 文件，在 [pool] 这一行下面加一行 max_idle = 20，README 里禁止改的除外，改完检查并回复 DONE。
4. Please append `max_idle = 20` as the first line of each [pool] section in settings/*.cfg (leave the file README.txt marks), check it, reply DONE.
5. For the cfg files in settings, add max_idle = 20 below [pool]; do not touch the CI-generated one. Reply DONE once checked.
