## Traps
- TR-READONLY: logrotate.d/遗留日志.conf is generated by the old system (README).
- TR-DECOY: 网关日志.conf has a compresscmd line; it is a different directive that merely starts with compress and gets no extra line of its own.

## Reference solution
1. bash: `find logrotate.d -name '*.conf' | grep -v 遗留日志 | xargs sed -i 's/^    compress$/    compress\n    delaycompress/'`
2. bash: `grep -rn -A1 'compress' logrotate.d` to confirm the target files changed and the protected ones did not.
Final answer: DONE (the four live configs have delaycompress under compress; 遗留日志.conf and the compresscmd line are unchanged).

## Why the answer is unique
Only the files and lines the README allows change, every other byte stays identical (4 files change).

## Five alternative phrasings of the task
1. 给 logrotate.d 里每个 .conf 的 compress 下一行加上 delaycompress，遗留日志的不要改。
2. 在 compress 之后插入 delaycompress（四个配置），README 里点名的例外保持不变。
3. logrotate.d 的配置统一增加 delaycompress，位置紧跟 compress，改完回复 DONE。
4. 把延迟压缩加到 web、支付、搜索、网关的日志配置里，遗留日志别碰。
5. Add a delaycompress line right under compress in each logrotate.d config except the generated legacy one, reply DONE.
