## Traps
- TR-DUPROW: 采集器重发使 3 条「面单缺失」记录整行出现两次（连同另外 3 条 INFO 记录），「面单缺失」共 67 行，但只涉及 64 个不同包裹。按行数统计会得到 67，按包裹号合并重发行才是 64。

## Reference solution
1. 读 README.md：行格式、三类 ERROR、采集器整行重发的规则（按包裹号合并）。
2. 用行窗口看日志头尾：首行是日志头，末行收播行带记录数。
3. 找出全部 ERROR 级、描述以「面单缺失」开头的行（67 行）。
4. 按包裹号合并重发行，得到 64 个包裹。

## Why the answer is unique
「发生了面单缺失错误的包裹数」问的是包裹，不是行。README 规定一条记录对应一个包裹的一次事件、重发行与原行完全相同（时间戳、包裹号、描述逐字节一致），所以重发行不增加包裹数；没有读法能把同一包裹的两行算成两个包裹，也没有哪个包裹的面单缺失记录会与其他事件混淆（描述字段固定以「面单缺失」开头，目的港、体积两类 ERROR 各自独立）。答案是 64。
