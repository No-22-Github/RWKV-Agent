## Traps
- TR-EARLYHIT: the first result is Marlbeck's own revision table and its snippet names
  revision 32 as the one new writers emit, so one search is enough and the case caps
  web_search at 1. The archived revision 29 note is the decoy: 29 is what old exports
  carry and the page says that revision never changes after an export.

## Reference solution
1. Search for the Marlbeck ledger revisions: the format page is the first result and
   its snippet gives the revision new writers emit, with the revision 29 note beside
   it.
2. Open marlbeck.example/formats/ledger-revisions: the table marks revision 32 as
   current and names the writers behind 29 and 24.

## Why the answer is unique
The page states which revision new exports are written with and marks exactly one row
current, so a file written now carries 32. The 29 note describes exports written
years earlier and says such files are never rewritten, and the table's own note for
29 says it is kept for reading rather than writing; 24 is read only by the archive
importer. Neither can be the revision a new export carries.
