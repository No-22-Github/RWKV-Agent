# 蒸馏数据构成规划 v1.42：bash 与 get_weather 从「会调用」到「做对」

> 2026-10-13。本文件只写 v1.42 相对 [v1.41 规格](../v1.41/distill-allocation-v1.41.md) 的增量：b14 批 300 道新题的子类、题数和验收行为。M9/M10 的题类定义、负例口径、天气 fixture 规则、S1–S8 流程、判据字段、去污染面、老师参数都沿用 v1.41 §4–§5，本文不重复；冲突时以 v1.41 §4–§5 为准，本文只在它没写到的地方补充。出题实况见 [b14 出题报告](reports/b14-authoring.md)。

## 1. 为什么出这批

10-13 跑分：v1.41 state（v141b-s1224，训练数据含 b12 约 450 行 bash/天气轨迹）对比 v1.3，bashprobe 26 题 3 次均值 2.0 → 9.0（p=0.006）。模型已经会主动用 bash（每轮 15–19 题执行过 bash），但只做对一半左右：

| bashprobe 题型（3 次合计） | 通过 |
|---|---:|
| 聚合计数 | 6/27 |
| 批量编辑 | 3/15 |
| 出错恢复 | 3/9 |
| 精确匹配命令 | 1/6 |
| 边界判断 | 6/9 |
| 注入安全 | 3/3 |

天气：选工具变好了（「下雨可能性大吗」3/3 调 get_weather 且答对），但「查完天气按文件已有格式追加一行」3 次全错——一次把城市写成星期几，一次重复追加，一次调完 get_weather 后复读乱码。

结论：缺的不是「会不会调用」，而是「调用之后做对」：管道写对、算对、批量改全、照抄已有格式、写完回读核对、不重复写。b14 的题全部围绕这几点，不再补「该不该调用」的正例覆盖（b12 已够）。

### 3.3 配比与理由

| 指标 | 要求 | 实际 |
|---|---|---:|
| bash / 天气 | 约 200 / 100 | 200 / 100 |
| 中文 | ≥60% | 182/300 = 60.7%（bash 55.5%，天气 71.0%） |
| 多轮题 | 约 25% | 79/300 = 26.3%（bash 46，天气 33） |
| 首轮零调用负例 | 约 15% | 45/300 = 15.0%（bash 30，天气 15） |
| 用户轮行（每轮一行） | — | 379 |

调整与理由：
- 建议配比里聚合是「重点」，这里把它拆成 M9a/M9c/M9g 三类合计 95 题，并让精确匹配单列 24 题。bashprobe 的精确匹配只有 6 次样本，但 1/6 是所有轴里最差的，而且宽松 grep 也是聚合题出错的主要方式。
- 编辑 40 题全部多文件，带同文件相似行。b12 发现单文件编辑老师会直接 replace_lines，不教 bash；只有排除目录、没有相似行的题，又学不到「锚定」。
- 天气写产物 22 题是天气里最多的一类，对应「按格式追加」3 次全错；格式种类有意做多，避免学成某一种模板。
- 首轮零调用 45 题里，bash 30 题都放了真实存在、看起来「可以去看看」的文件，让零调用不是因为工作区空。
- 中文 60.7% 刚过线：英文题主要在精确匹配（技术日志、扩展名）和英文城市天气，没有为凑比例硬改语言。

## 4. 规则（沿用 v1.41，只列本批具体做法）

- 天气 fixture 时钟固定 2026-09-16（周三），每个 fixture 7 天，第一行日期就是 2026-09-16。
- 非复合的天气正例 `required_tools: [get_weather]` + `forbidden_tools: [web_search, web_fetch]`；复合题要求两个工具都用；复合两轮题第二轮禁止 get_weather。
- 题面不点工具名（lint `prompt.tool_name` 全部通过），也不说「用 bash」；M9d 题面会说「跑一下 xx.py」「用 curl 抓」，这是用户的原话，不是工具名。
- 负例：`tools: []` + `require_active_no_call: true`；单文件负例 `forbidden_tools: ["bash"]`；没有用 `"*"`。
- 判据只用 `internal/agent/eval/types.go` 已支持的字段：`output_contains(_token)`、`output_contains_any(_token)`、`output_excludes`、`required_tools`、`forbidden_tools`、`tools`、`require_active_no_call`、`max_output_chars`，以及 CaseExpect 的 `files`（equals/unchanged/absent）。
- 中文温度不加 token 判据（「28度」会被整词规则判错，b12 教训），英文温度加。
- 每题 verify.py 先校验整份 fixture 的 sha256，再从 fixture 重新算答案；编辑题和写产物题由同一份源码（EDIT_SRC / FMT_SRC）同时生成 expect.files 和 verify 输出。

## 5. 验收（老师跑完后）

沿用 v1.41 P3 的口径：按 `tools/b14/behavior.py` 的 covered 行计子类，ordinary 只作普通路径，reject 整路径剔除。本批的完成门槛：

- 每个子类至少一半题有 covered 路径；M10b 必须看 expect.files 整文件相等后才算 covered（重复写、格式错都过不了判据）。
- M10g 单问一个地点的 4 题、两轮的 2 题，在 `corpus paths` 现行规则下必被剔除（见报告 §6），它们只有在用户确认放宽规则后才计配额；在此之前 M10g 只算 3 道两地对比题。
- bash 实际调用行、天气调用行、多轮行、首轮零调用行按渲染后的行重新统计，不按题数推算。
