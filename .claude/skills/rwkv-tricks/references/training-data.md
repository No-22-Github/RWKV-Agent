# 训练语料渲染（state tuning / MiSS / LoRA）

## 字节对齐

- **训练格式与推理格式逐字节一致**，包括空 think 历史、工具目录、提醒措辞。换个前缀就掉分。
- **训练片段从 `Assistant:` 之后开始，把冒号后的空格划进训练片段**。推理时生成点以 `Assistant:` 结尾，
  模型要生成的第一个 token 是 ` <` / ` {` / ` Hello`；如果空格留在 prompt 侧，训练时这些 token 被拆开，与推理分词不一致。
- **终答的训练片段必须带终止符**（`\n\n` + EOS）。不带的话模型答完会续写 `✿text1✿` 或下一轮 `User:`。
- 若训练器用"字符偏移"标注 loss 区间（loss_spans），注意是字符不是字节；分段各自分词时不会自动加 EOD；超过 ctx 可能被静默截断。
- 有的旧训练器对全文算 loss 且不加 EOS，token 0 无法从文本编码出来——先确认训练器是否支持掩码。
- 多轮数据按用户轮切行，别把多轮拼成一行。

## 数据构成

- **去污染**：测试题泄漏进训练集是常见事故；英文 n-gram 去污染对中文题无效，要单独处理。
- **行为分布要配平**：
  - 首动作 100% 是调工具 → 弃权/追问能力被洗掉（irrelevance 类大幅下降）。必须有"不该调用"的反面样本。
  - 中文 0 行 → 中文题崩。
  - 纯值终答占比过高 → 训出"短垃圾终答"。
  - 收尾阶段（工具用完写答案）是 Agent 头号死因，语料里要专门覆盖"读到即答"。
- 语料的包络形状（信封、多调用数组）会泄漏进作答阶段，示范必须严格是想要的行为。
- **老师轨迹出包前必扫**：空转、复读、重复调用、点破模拟环境。fixture 别用 `.example` 域名，老师会识破并空转搜索。
- 老师自报身份（"我是 Qwen/DeepSeek"）不必特意筛。

## 超参与局限（7B，参考量级）

- MiSS：r16、2 epoch、lr 2e-5～3e-5 较好；≥3e-4 练坏。
- 带思考训练的模型推理时必须配思考格式，否则大量违约。思考微调后日常短答会遗忘，可混通用中文带思考蒸馏数据（如 HF `dengxiaodi/deepseek-v4.1-flash-distill-zh-2k`）。
- state tuning 主要学到"进入工具循环"的格式，学不到"读对、算对"；7B state tuning 在通用 Agent 基准上有一堵明显的墙。
- 工具倾向随 checkpoint 呈锯齿（爱调 / 少调二态），选点要看行为分布，不只看总分。
