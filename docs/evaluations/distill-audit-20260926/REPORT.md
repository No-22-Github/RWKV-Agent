## 2. 高优先级问题

### P1：独立答案校验存在 fail-open，609/609 不能当成 609 个答案都核验过

`internal/lab/bank/verify.go:187-191` 对无法识别的 verify 输出形状返回 `ok:true` 加 warning。本次 **92 题**出现 `verify_shape_unknown`；另有 57 道 smalltalk 按设计跳过 verify，30 道 sabotage 因无文件跳过。这些数量不能简单相加为不同题数。

具体反例 `nt-5278`：verify.py 输出 `expected_contains_any`，校验器不认识该格式。审阅在隔离副本里把题目 `output_contains_any` 改为 `DELIBERATELY_WRONG_AUDIT_SENTINEL`，`bank verify` 仍以 **exit 0** 通过。破坏测试只证明删掉 fixture 行能让脚本失败，没有证明脚本的答案与评分契约一致。

这道题还有真实语义错误：题面要求填入 CREATE 和 INDEX **之间**的单词，收下 `CONCURRENTLY` 两条轨迹；但 PostgreSQL 正确形式是 `CREATE INDEX CONCURRENTLY`，该词位于 INDEX **之后**。NOTES 把错误位置也解释成正确。因此它展示了“题面、判据、老师一起犯错而全绿”的实际风险。

依据：[PostgreSQL CREATE INDEX 官方语法](https://www.postgresql.org/docs/18/sql-createindex.html)。对应数据：`bench/distill/cases/v1/notool/nt-5278`；探针：`runs/distill/audit-20260926/negative-probe.log`。

建议：显式支持并比较关键词契约；非豁免的未知输出形状应失败。对这 92 题重新做契约/事实审查，修题后重新采样，不手改老师轨迹。

### P1：直答配额被本地查找和可有可无的调用替代

`internal/agent/eval/scoring.go:43-52` 明确将 `tools: []` 作为诊断指标，不纳入任务通过条件。这对评测“答案正确”和“调用纪律”分开计分有理由，但蒸馏选路只筛 passed，未补上训练目标的行为门槛。

最终新语料中有 **531 行**对应显式 `tools: []`，其中 **387 行仍调用工具**。不能把这 387 行都判成错答案；它说明该字段不能保证直答教材。

更严重的是题目设计本身：**45 道 stable_fact 全部标注 ref_calls=1**，最终 85 行全部调用工具。抽查 `nt-5053` 问某水族馆潜水日志保存期限，答案只在本地 runbook；`nt-5266` 问某信托的锅炉检查负责人，也必须读文件。它们是有效的本地检索题，却不属于无需工具的稳定常识。

### P1：clarify 标签不代表先问再做，部分题目本来就不需要反问

**65 行 clarify 全部先调用了工具；55 行终答没有问号。** 没有问号本身不是语义错误，但结合实际轨迹，不能据此声称已经学到“第一轮先澄清”。

`hyb-5043` 问库存里有多少 M8 螺栓。两条轨迹先读表，给出 228 总数及 132/96 分类，附条件式说明；第二轮直接回答 132。第一轮按普通语义已经合理回答了问题，题目却把它当“歧义反问”。关键词 `specif` 等会在普通说明中命中。

另一类如 `nt-5320` 确实问了缺失的租期，但先执行 6 次调用。因此应区分“读资料后发现缺少条件”和“调用前就能识别缺参”，不能只看一个 clarify 标签。

建议：把有用的现有轨迹归入“先查后条件式回答/澄清”；另建确实缺少决策必需参数的题。检查是否获得必要信息、是否过早行动，不要把新增问号当作唯一修复。

## 3. 实际训练用途与局限

### 行为分布仍偏工具调用，短收尾目标未充分实现

- 全集零调用 **208/1586 = 13.1%**；纯新数据 **208/1035 = 20.1%**。
- 208 行中 **62 行来自第二轮历史已带答案的直接收尾**；第一轮零调用仅 146 行。它们都是合法训练行为，但不能混作“初始判断无需工具”的覆盖。
- 新数据的 827 条有调用行中，只有 **113 行为 1–2 次调用（13.7%）**，714 行为至少 3 次。新数据仍主要教多步调用。
- `refuse` 77 行中只有 **4 行**为零调用；其余多为查过工作区之后拒绝。部分请求确实需要先核实能力，不能一概剔除，但要按目标分别采样。
- smalltalk 的 57 行全部零调用，是这次补充中行为目标最清晰的一块。

因此“补更多行”不是第一优先级。应按真实动作统计配比，按原题限制不同路径的总权重，避免有两条路径的工具题天然压过只有一条路径的直答题。

### 全文训练可读，但不是 assistant-only 的动作监督

pack 生成的 `train.jsonl` 只有 text；当前相邻 `rwkv_lightning_cuda/src/state_tuning/dataset.cpp:116-133` 也明确只接受 text，拒收额外字段。当前导出兼容这种读取方式，`rows.jsonl` 保留的 loss_spans 不会因此自动生效。

本次统计，loss_spans 覆盖内容只占总文本 **约 7.3% 的 Unicode 字符**，其余主要是系统/工具说明、用户输入、工具回执和历史。这是字符占比，不是精确 token/loss 比例。全文 loss 会把这些上下文也作为预测目标；移除 119 条恢复前缀有帮助，但不能等同于已实现动作掩码训练。

适合作为小规模 state/full-text 试验输入；若目标是有效蒸馏老师动作，优先接通 masked loss，并核对码点偏移到 tokenizer 标签的转换。这里没有对训练器做运行验证。

### 测试污染仍在，不能用全 workbank 分数证明泛化

最终 **551 行（34.7%）**标记 `seeded_from_test=true`，来自既有 base700。它们是已知测试种子衍生数据，不是本次 decontam 为 0 就变干净了。

已有决定是保留它们，但评测必须区分 36 道泄漏种子题与其余 112 道题。更有归因价值的是在相同训练预算下比较新蒸馏子集与混合集，并另留按原题/家族隔离的验证集。当前 pack 只有 train，没有独立验证划分；切分时不能随机按行，让同题不同路径或两轮落到两边。

### 可复现性和覆盖边界

b01–b03 的题目与动作脚本均已入库，可离线重放，这是本批的主要工程优点；错误路径、协议重试、工具失败、强制收尾有明确过滤，重放还会重新执行工具并核对脚本。

但 base700 单凭入库脚本不能重建：还依赖 gitignored normalized records。本次能重建是因为本机恰好保留了这些文件，干净克隆不能据此保证可复现全部 1586 行。
（2026-09-29 更新：normalized records 已入库 `bench/archive/workspace-agent-700-20260920/generated/normalized/all.jsonl`，干净克隆现可复现 base700 全部行；上一句的限制自即日起不再成立。）

入库脚本没有逐路径保留原始 teacher run/采样/原始 trace 的完整绑定；本次验证了重放行为，没有独立重新证实历史 pass@3 或老师来源。当前是英文、合成的小工作区与 fixture web 环境，约 310 万 token；对中文、真实互联网和长上下文任务的适用性未被验证。

## 4. 建议处理顺序

1. 修复 verify 未识别格式仍通过的漏洞，复查 92 题；隔离并修正 `nt-5278` 这类语义错题，再重新采样。

3. 导出新蒸馏专用集与含 base700 的混合集，明确污染来源；按原题/家族留验证集，按真实零调用、首次直接回答、短路径比例配比。
4. 再做受控训练实验，优先观察首轮不必要调用、重复调用、正确终止、澄清后的完成率；报告干净测试子集。训练收益必须由实际结果判断。
