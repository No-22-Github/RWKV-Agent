# G1L 基模 × 新格式 agent-wire-think-v2.0（iRWKV，2026-10-31）

**结论：G1L 基模在 v2.0 和 v1.0 下总分打平（v2.0 两遍 173/174，均值 173.5；v1.0 同日两遍 168/175，均值 171.5），两遍合并逐题 +94/−90，p=0.83。但 v2.0 改变了模型的行为：**

- **一旦历史里出现空思考块 `<think></think>`，基模大约八成的步骤会照着写，自己不再思考。** v2.0 下带历史的步骤空思考占 77–78%，v1.0 只有 0.1–0.2%；首步两边都是 0%。
- **步骤变多，上下文更容易撑爆。** 每题平均模型调用从 5.0 次涨到 6.9 次；超过 32768 token 被服务端拒绝的题从 12/10 涨到 22/18，集中在 bashprobe。
- **用户多轮的 bfcl 状态题明显掉分：v1.0 20/20，v2.0 9/20。** 典型失败：第二轮用户问"刚才那个值是什么"，模型直接写 `></think>` 跳过思考，随手调了一个无关的计算器，再把上一轮的回答照抄一遍。

这是基模的基线，不是 think-sft 适配器的成绩。think-sft 训练数据正是"历史写空块、当前步照样思考"，所以给存档跑分时，除了总分，还要看两个数：**带历史步骤的空思考率**（基模 77%，应明显下降）和 **bfcl 多轮状态题**（基模 9/20）。

## 空思考与步数

按模型调用统计：

| 组 | 首步空思考 | 带历史步骤空思考 | 每题模型调用 |
|---|---|---|---|
| v1.0 k0 / k1 | 0.0% / 0.0% | 0.2% / 0.1% | 5.02 / 4.95 |
| v2.0 k0 / k1 | 0.0% / 0.0% | **77.4% / 78.4%** | **6.84 / 7.00** |

v2.0 唯一的区别就是历史步骤前面的 `<think></think>`（和压空行）；基模没见过"历史空块、当前步要想"的数据，就照着历史的样子续写。不思考的步骤并没有拉低总分，但它让模型在多轮里不回看上一轮、在 bash 题里多走步，把上下文撑到 32K 上限。

## 跑 think-sft 存档时

- 用 `--profile agent-wire-think-v2.0`，并按训练数据的目录加 `--tool-catalog agent-tool-v3.2`（v2.3 两组考卷也是这样）。清单默认的 agent-tool-v2.0 是这里为了和 10-29 iRWKV 两组可比才用的。
- 适配器要挂在 rwkv_lightning 端点上跑（iRWKV 不能按请求挂适配器）；那边前缀缓存开着、状态精度不同，和这里的基线不能直接配对，基线需要在同一端点上重跑。
