## 2. 分类细节

### 2.1 A：收尾失败

和 `closeout_tool_call` 同源：重复调用被拒后强制收尾，模型仍吐调用，harness 用兜底文案作答。分类脚本按「有输出」把它记成答错。
三次副本里这 8 题都有至少一次直接记为 `closeout_tool_call`。

### 2.2 B：短垃圾终答（新失败模式）

- 15 次里 13 次发生在**正常决策阶段**，不是强制收尾：模型读完工具结果，第一个 token 就跑偏，写一个短词后立刻 `\n\nUser:`。
- 推测成因：训练终答 58% 是几个 token 的纯值且紧跟 `\n\nUser:`，模型学到「写个短东西就收尾」；没把握时随便吐一个短 token。
  none（无 state）几乎没有这种输出，是 state 带来的。
- 另一半是长退化：复读（`User/`、`4`）、回显 README 原文或自己的计划、`_tool_call>{…}` 残片。

`replace_lines` 还出现缺 `start_line/end_line`、用一行范围替换多行内容导致行重复（hyb-0005 total_lines 3→5）。

## 3. 对 v1.4 的含义

| 优先级 | 问题 | 方向 |
|---|---|---|
| 高 | B 短垃圾终答（15） | 终答形态去偏：纯值终答占比从 58% 降下来，补「先引用证据再给值」的短句终答；排查训练行里短终答 + `\n\nUser:` 的分布 |
| 高 | A 收尾失败（8，另有 `closeout_tool_call` 22） | N10 收尾恢复样本加量，覆盖写任务与多步脚本任务 |
| 高 | C 写任务（13） | write+script 只占 6.4%：补「写完回读校验再 DONE」、`replace_lines` 行号正确用法、保留注释、没写不许 DONE |
| 中 | D 表格 / 日志处理（14） | N11 补足：混合日期 / 单位 / 时区归一，用 `data_query` 或 `calculator` 做筛选和汇总，`search_text` 拿行号 |
| 中 | F 信源与完整性（8） | 官方页优先于博客 / wiki；配置要看完覆盖层；目标不存在时不拿相近项凑答案，而是**写一段说明**：查了哪些地方、缺的是什么、用户可以怎么补——不能只回 `UNKNOWN` 几个字，否则又练成固定短词 |
| 低 | E 心算（3） | 算术一律调 `calculator`，零调用直答只留给不需要计算的题 |
