**6.1 sol 可以继续承担固定格式题的起草，但仍需要主审，不能自动批量收题。** 本轮完整首版冻结后，主审发现并修订了 3 题的判分/题面问题，另校正了 2 个难度标签。修订后未发现需要废弃重出的实质错题；20 题全部保留 draft，其中 **17 题通过现有 lint/verify，3 题受已知 verify 破坏探针误报阻塞**，不宣称本期验收全绿。

题目在 **`bench/exam/pilots/sol-20261015/cases/<scenario>/<id>/`**，采用 `*-12001` 起号段，共 20 个目录 / 60 个附件文件；未并入自动导入目录、未改正式 378 题考卷、未提交或推送。逐题清单与 case.json SHA-256 为同目录 `gap-fill-sol20-review.json`。

DeepSeek 首轮 **18/20（90%）**，修订后完整复跑 **15/20（75%）**，两份均 invalid=0、run check 通过。所有失败已逐题阅读，均为老师实际执行失败；两次输入哈希不同，不能当作同题同配置重复测量求均值，更不能据此判断 sol 出题质量变差或变好。

## 仍存在的验证器与评分边界

1. 最终 bank lint **20 checked / 0 violation**；bank verify strict-shape **17 passed / 3 failed**。nt-12001/12002 的答案来自用户消息，破坏旧文件不应改答案；fs-12002 探针删除的是保留的 `.tmp.txt` 首行，删除集合及口径文件应不变。三题答案匹配都通过，仅 sabotage 未检出。17 个 passed 中，nt-12004 是 refusal 跳过、nt-12003 的无文件 sabotage 跳过，不能将其宣传为独立数值复算通过。没有为通过检查加入无关断言，不能声称 M1 全通过。
2. 删除题 oracle 按动态规则重算保留映射；原生 bank verify 不直接比较 absent，另有真实 App 盲解终态检查和正反例自审支持，不能把单个 sabotage 结果当成完整删除逻辑验证。
3. 两道脚本按 expect.run 的实际 stdout 判分，源文件不锁实现，输入保护；当前固定输入仍无法排除硬编码整份正确输出。作者和主审均不声称验证所有未来数据。
4. 反问和拒绝的关键词规则没有完整语义理解，可能漏掉非常规同义表达，也不能穷尽“拒绝某操作却假称完成另一操作”的矛盾话语。主审去掉了误伤否定的粗暴排除；不能以有限词表冒充语义完备。
5. 模板题与 CSV 导入题的严格字节格式对模型可见，属于其任务约定；这不等于通用文件语义评分已解决。额外新建、但未列在文件预期中的文件，也不由原生 files 规则全面穷举检查。
