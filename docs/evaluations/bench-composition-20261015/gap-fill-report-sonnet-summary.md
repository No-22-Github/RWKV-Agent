## 4. 要你决定的事

1. **新题要不要并入考卷**。并入要先处理下面第 2 条，并且考卷会从 378 变成 476 题，历史成绩需按题号对齐着看。
2. **闲聊题和 lint 冲突**：g2 的 3 道闲聊题（nt-13001～13003）按需求单不该锁关键词，但 `bank lint` 要求闲聊题必须带 `output_contains_any`，目前报 3 条违规。二选一：改 lint，或给闲聊题塞一组很宽的词。
3. **评测环境的日期没冻住**：评测把「今天」固定在 2026-09-16，但 bash 里的 `date` 拿到的是真实日期，DeepSeek 用 bash 算「昨天」就会算到 10 月。log-13107、log-13112 题面里有「昨天」，有波动风险。建议给 sidecar 的 date 也固定时钟（要改 harness）。
4. **需求单的两条判分规则建议改掉**：
   - 纠正题「用 output_excludes 排除旧答案」→ 改成「第一行必须给出新答案」。三个批次独立撞到同一个误判。
   - 加一条「答案数字不得出现在题面里」：g4 的 doc-13317 原题面写「2020 年 11 月入职」，答案是 11 天，答错的回答也因为复述了题面里的 11 被判对。
5. **verify 破坏探针**对「答案来自用户消息」「多轮题」「长文件里同值数字」误报很多（各批合计十几条），是否接受或改检查器。
6. g4 文档题：需求单要求文档 30～60 KB，又要求答案不在前 64 KB，两者矛盾。现在按 30～60 KB 做，模型一次就能读完全文；如果要逼它分页读，得放宽到 70 KB 以上。

### 为这一期补的评测能力

- **bash 时钟固定**：sidecar（`native/justbash/sidecar.ts`）开工作区时可带 `now_ms`，用 `AsyncLocalStorage` 只对这个会话生效，App 会话不受影响；评测把与 datetime 工具相同的 2026-09-16 10:00 传给 bash；题目文件的修改时间统一设为 09:00。测试：`TestBashToolPinnedClockIsPerSession`、`TestProductBashSeesBankClock`。
- **`review_before`（轮字段）**：`accept` / `reject`，这一轮开始前模拟用户在改动面板全部确认或全部拒绝。测试：`TestReviewStagedChanges`、`TestReviewBeforeValidated`。
