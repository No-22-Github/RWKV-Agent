# 新考卷三组横比：基模 / v1.41 State / v2.0 MiSS（2026-10-16）

## 结论

- **State（v141b-s1224）和 MiSS（r16-lr3e-5）都比基模高约 25 个百分点**：两遍平均 46.9% / 46.4% 对 21.4%，符号检验 p < 1e-27。
- **State 和 MiSS 总分分不出高低**：平均只差 0.5 个百分点。有 166 道题两边表现不同，State 好 87 道、MiSS 好 79 道，p = 0.59。
- **两者强项不同**（下面 p 值都是单个题型内的符号检验，没有做多重比较校正，只能当线索看）：
  - MiSS 好在多轮对话（60.8% 对 43.2%，0/8，p = 0.008）、改写文本（100% 对 33.3%，0/8，p = 0.008）、概念问答（100% 对 75%，0/7，p = 0.016）。
  - State 好在找缺失的配置键（85% 对 25%，7/0，p = 0.016），workbank 整体也略高（35.1% 对 24.8%，27/14，p = 0.06）。
- **三组共同的短板**：计算（tabular、logs、script 场景）和写文件。脚本类（script 场景）27 道题，三组都接近 0。
- **两遍之间很稳**：每组两遍的总分只差 0–3 题，两遍结果不同的题有 23–57 道，正反两个方向相互抵消。两遍足够，不需要补第三遍。

MiSS 用带思考格式，是因为它的训练语料和 10-15 那次跑分都用 `g1k-think`。在不带思考的 `g1k` 下，它会把思考内容写在工具调用前面，被判违约：作废前的一轮试跑里，88 题中有 71 题（81%）被判违约（见下文「作废的试跑」）。

带思考时决策预算的实际值：run.json 里 `decision_max_output_tokens` 显示 2048，但带思考时客户端实际按 `max_output_tokens: 4096` 发请求，和 10-15 一样。k0 的 MiSS 有 1019 次思考决策：中位数 81 token，p99 790，超过 2000 的只有 1 次（log-0005，3871 token，模型在思考里逐行抄了一遍日志），以跑满上限结束的也只有 1 次，截断影响可以忽略。
