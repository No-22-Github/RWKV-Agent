# harness v26 重复调用重试 × G1L 7.2B 正式版（iRWKV，2026-11-03）

**结论：v26 和 v25 总分无法区分。** v25 两遍 192/203（均值 197.5，34.8%），v26 两遍 207/201（均值 204，35.9%），两遍合并逐题 −66/+79，p=0.32；同配置两遍互比的翻转（−25/+36、−37/+31）和组间翻转一样大。

改动本身起了作用，但救回的题很少：

- **因重复被强制收尾的题** 218/190 → 131/138，**收尾阶段吐工具调用的步数** 296/286 → 180/225。
- 第一次被拒之后（两遍合计 360 次），模型的下一步：直接回答 105、换别的工具 95、**又原样重复 96**、去改文件 64。也就是约四分之一照样重复（随后照旧强制收尾），这和 10-03 `dup-continue` 的循环是同一个现象，只是限了一次。
- 出现过重复调用的题，最终通过的 v25 23/22、v26 23/25，几乎没变。拿到第二次机会去改文件的 64 次里只有 8 题通过。

**更值得注意的是重复调用本身有多普遍**：G1L 正式版在 `agent-wire-think-v1.0` 下，约 36% 的题（190–218/568）至少重复过一次已成功的调用，这类题通过率只有约 11%。这是模型侧问题，harness 只能止损。

## 判断

- **好处在考卷上测不出来**：总分、各场景差距都在两遍波动内，出现重复的题通过数几乎不变。
- **坏处是实打实的**：每题约慢 7%、生成多约 17%。
- **考卷外可能的好处**：App 里像 11-02 改配色这种"读完想改却又重读"的简单任务，v26 多给了一次改文件的机会；强制收尾每遍少约 70 题，其中一部分用户会从兜底模板变成真的回答或改动。这部分没有数据支撑。
- **决定：保留 v26。** 不掉分，换来 App 里少一部分整轮作废；如果更看重速度，退回 v25 也没有可测的损失。

## 下一步建议

- 重复调用的代价，harness 最多只能从"整轮作废"降成"多跑一步"。
- 重复调用要靠训练数据治：语料里补"读过文件后直接改"和"被拒重复后换路"的轨迹，比在 harness 里加更多重试更有效。
