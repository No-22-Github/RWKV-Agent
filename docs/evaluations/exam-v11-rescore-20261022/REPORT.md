# 考卷 v1.1：放行 calculator 后重算历史分 2026-10-22

## 改了什么

- **判据（agent-exam-v1.0 → v1.1，hash `0c0101883de4…`；quick `dc2ae8b9a8ac…`）**：notool 自出题 30 道、BFCL irrelevance 移植题 20 道，在原有 `require_active_no_call` 旁加 `"no_call_allowed_tools": ["calculator"]`，题目 `tags.version` +1。题面、题集、其他判分项不变。
  理由：7B 连 3.9 和 3.11 都会比错，用计算器确认是产品想要的行为；BFCL 原意是"没有相关函数"，而我们的目录里 calculator 恰是相关工具；nt-12001 等自出题的陷阱是"别读旧文件"，不是"别算"。
- **判分器**：`Expectation.NoCallAllowedTools`（`internal/agent/eval/scoring.go` `onlyAllowedCalls`）。一轮里所有调用都落在名单内、且结局是正常调用（不是协议失败）时，仍算主动不调工具。没写这个字段的题判法不变，所以没有升 scorer 版本，改动由 exam hash 记录。
  BFCL missing-required 5 题、bfcl-multiturn 等其他带 `require_active_no_call` 的题没有放行。
- **工具（agent-tool-v3.1 → v3.2）**：v3 calculator 支持最外层比较 `> < >= <= == !=`，返回 true/false；见 `docs/design/agent-tool-v3.md` §12。v2.0 不动。

## 重算方法

不重跑，用 `rescore_v11.py` 读已有 `summary.json`：只有当一题在 v1.0 下的失败理由**全部**是 `active no-call required`、结局是 `called_tool`、且调用的工具全是 calculator 时，才改判通过。这正是新判分器的规则，答案检查照旧参与（失败理由里有答案错误的不会翻）。逐 run 结果见 `rescore-table.md`。
10-15 那两组是 378 题的旧考卷，不在表内。
