# 考卷 v1.2 与判分器 scorer-v4：按判分审计修判法，重算历史分 2026-10-23

## 改了什么

起因是 10-23 的判分审计（42 遍 run 逐题对拍）：确认冤判约 24 题、漏判 12 题，主要压低了 Qwen 的分。

**判分器（`rwkv-agent-eval-scorer-v3` → `v4`，`ac2405a8`，`internal/agent/eval/scoring.go`）**

- summary 兜底不算模型答案：作答阶段一直吐工具调用、harness 写"这次没能直接给出回答。我查过的内容…"时，答案按空处理，所有答案检查都不过。原先这段话里列出的网址、路径、查询词会撞中词表（web-8002 主力 6 遍全靠 `release-notes` 过）。opener 兜底（harness 只起了个头，正文是模型写的）照常判。
- `output_contains` / `output_contains_any` / `must_state_unverified` 拉丁字母不分大小写、去掉 `**`（code-8001 的 kestrel、nt-14010 的 **Staging**、wth-0124 的"每周**一闭馆"）。`output_excludes` 只去 `**`、仍分大小写，因为 `UNKNOWN` 是字面弃权标记，正文里的 "unknown" 不是它（log-8001）。
- 首行规则：首行以冒号结尾（"Based on the current prices:"、"资产文件有："）只算引导，改看它后面的首末行。首行本身给出陷阱值的仍判错。
- `expected_number_in_text` 只读首末行、带加粗的行和"答案："之后，不再扫全文：明细表里出现期望值不能救一个错的总数（doc-13317、code-0011、doc-13314）。
- 新字段 `output_contains_in_order`：按顺序出现即可，箭头链、逗号、编号列表都认。
- 文件 `equals` 容忍末尾换行（bsh-0020：10-21 前 append_file 不补换行）。这一条是收尾状态检查，旧 run 没存工作区，离线重判算不到，只对新跑分生效。

**考卷判据（agent-exam-v1.1 → v1.2，hash `88c8d0bf821f…`；quick `14f184f0e146…`；题面与题集不变）**

- hyb-8004、hyb-8008 第 3 轮：复查后答"5""18"即可，改为 `expected_number` 加原有排除项。
- wth-0120/0121/0122："查不到"词表补"没有找到、不支持、暂不支持、未收录、不在支持"。
- log-13301：改用 `output_contains_in_order`。
- 放行 calculator：log-13112、cfg-13110、cfg-13210、doc-13212 的记忆轮，bsh-0149/0152/0153 的直答比较题。只问命令的 bsh-0150/0151/0154/0155、概念题 wth-0126~0129、BFCL missing 与 multi_turn 不放行。
- cfg-0011：删掉 `not `、`no `、`n't` 这类泛词，改为具体的"不存在"说法，加 `output_excludes` 排除"resolves to 30"等陷阱结论。
- doc-13212：最后一天也认 9/14（含当天计法）。

**没改的**：审计疑似档中的 doc-8014、hyb-14129 词表，cfg-13401/13402、web-13412 的陷阱值排除，nt-14005 中英混答，doc-13409 完整文件名，数字集合不看键值对应，scr-8003 的 2458.0。

**App 行为（harness `rwkv-agent-eval-v22` → `v23`，`57f55c66`）**：没有 `<tool_call>` 包裹的 JSON 一律当正文。以前有三处会解析裸 JSON：终答整段是 JSON 时被当成违规换成"模型输出不符合答案契约"（42 遍里 9 次，如 log-14144 计数全对被换掉）；`{"name":…,"arguments":…}` 被当成"缺信封"的工具调用报协议错（4 次）；作答阶段的裸 JSON 被当成工具调用。三处都去掉了。离线重判算不到这项，要新跑分才能体现。

## 重算方法

`go run ./cmd/rwkv-lab exam rescore [--flips out.tsv] <run 目录>…`（新命令，`internal/agent/eval/rescore.go`）：读旧 `summary.json`，用当前判分器和 v1.2 题目判据重判每一轮，不重跑。收尾状态检查（expect.files / run / max_calls）和 Primitive Bench 失败照抄旧记录。

自检：用 scorer-v3 + v1.1 判据跑这个命令，42 遍的分数与 `exam-v11-rescore-20261022/rescore-table.md` 逐遍一致。

`rescore-table.md` 的"旧分"是 run 当时记录的 v1.0 判定；`flips.tsv` 列出每一处翻转和原因（含 v1.1 的 calculator 放行）。

## 结论变化

- RWKV 各组变化在 ±2.5 题内，排序不变。冤判修正（首行、大小写、追问轮、计算器）和漏判修正（summary 兜底、数字只读显眼位置、cfg-0011）大致抵消。
