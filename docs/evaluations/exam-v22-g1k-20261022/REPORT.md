## 5. 失分归因（Sonnet 子 Agent，逐题读轨迹）

退步题（两遍合计 v2.1 通过次数多于 v2.2）两个臂并集 101 题：calculator 判法 5、波动 22、真实退步 74。逐题表 `regressions.tsv`。

已确认的事实：
- **本地题先上网**：非 web/notool/hybrid 场景首步 web_search，v2.1 两遍共 2 次，v22-v2 17 次、v22-v3 19 次（cfg-0008/0009/8011、doc-0006/0009/8011、log-0011 等），这些遍全部失败。较可能来自 b22a（50 个 case 里 24 个首步 web_search，提示里带公司/产品名）。
- **v2.0 目录错配**：v22-v2 的 replace_lines 报错 78/218（36%），v2.1 7%、v22-v3 7%；read_file 带不存在参数（end_line、max_lines 等）11 次。v2.2 的公平口径是 v22-v3。
- **在原本稳过的题上更爱用 bash、更常进兜底**：v2.1 两遍都过的 281 题上，bash 均值 0.13 → 0.21 / 0.34，兜底率 1.4% → 2.7% / 4.3%；全卷总体工具调用数并未上升。

较可能：
- 试错空转来自补全的 99 个 case 与 21 个 flail_retry 样本：失分题与训练样本的任务族、命令写法成对相似（log-0005 ↔ log-32101，bsh-0160 ↔ tab-32204，tab-0010 ↔ tab-32317 等）。v22-v3 下补全家族 113 题掉 14 分（占总降幅 44%），但 v22-v2 下只掉 4 分，两臂不一致。

**考卷 v1.1 重算（同日补记）**：放行 calculator 后，v2.1 298.0、v22-v3 286.5（+69/−81，p=0.37）、v22-v2 277.0（+56/−76，p=0.10）、基模 133.0。
见 `docs/evaluations/exam-v11-rescore-20261022/REPORT.md`。

## 6. 考卷判法问题（已在 v1.1 修正）

notool 与 BFCL 移植来的 irrelevance 题要求"任何工具都不调"，调 calculator 也判错（bfcl_irrelevance_2/14/19/21、nt-12001 等）。BFCL 原意是"没有相关函数"，而我们的目录里 calculator 恰是相关工具；
nt-12001 的陷阱本是"别读上周的 csv"。用户取向：7B 用计算器确认是合理的（G1L API 答"3.11 比 3.9 大"）。建议放行 calculator 这类无副作用调用，或替换这批 BFCL 题；改后历史分需重算。
另：calculator 不支持比较运算，13B 问"3.9 和 3.11 哪个大"时连续 3 次报错，建议支持 `>`/`<`，或在报错里提示 `max(a, b)`。
