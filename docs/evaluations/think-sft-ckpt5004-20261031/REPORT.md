**头号原因：该直接回答的题去调工具。** 考卷里参考答案零调用的 54 题，第一步就直接回答：v2.3 38 题，本存档 25/27 题；多出来的是 `list_files`（10/9）、`web_search`（4/4）、`bash`（3/3）、`read_file`（3/3）。v2.3 答对而本存档答错的 20 道 notool 题，几乎全是解释代码、讲概念、改写文本、闲聊——它在思考里先说"我得先看看工作区里有没有相关的文件"，然后列目录；改写题还把结果写进了文件。

推测：think-sft 包里开源 Agent 轨迹（Nemotron tool_calling 2971 条等）几乎都要调工具，自有数据里的"直接回答"被稀释了。未验证；要看后续存档。

**好的变化**：带历史步骤的空思考 0%（v2.3 也是 0%，因为它用 v1.0 格式；基模在 v2.0 下 77%）；bfcl 多轮状态题 20/20（基模在 iRWKV 上 v2.0 格式 9/20）；每题模型调用 5.40/5.31，与 v2.3 的 5.32 相当。

## 通用评测：中文思考绕圈

IFEval 中文失分集中在**思考停不下来**：思考没闭合 35.6%（基模 9.4%），复读 32.8%（基模 16.1%），思考中位 2433 字（基模 663 字）。看原文，绕圈的是一种"规划式"中文思考（"用户要求：…需要…可以…确保…"），同一组句子反复出现直到撞上限，有的在回答里列清单时循环。这种口吻像 think-sft 中文日常对话的老师（Qwen3.8-Flash 重答的 WildChat）。英文没有这个问题（IFEval 英文复读 16.1% vs 基模 15.6%）。

MT-Bench 中文第一轮掉 0.9 分、复读 14.8% → 24.1%，同一个毛病。C-Eval/CMMLU 的复读率两边接近（~35% / ~20%），分差不显著。

GSM8K 正相反：思考大幅变短（中位 2499 → 384 字）、复读 18% → 2.4%，`\boxed{}` 抽到率 81% → 98%，准确率 +6.6。
