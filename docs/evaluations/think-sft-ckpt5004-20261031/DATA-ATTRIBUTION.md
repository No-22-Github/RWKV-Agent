## 2. 大包 Agent 数据：自有 vs 开源

| | 自有 v2.3 | 开源 10 个来源合计 |
|---|---:|---:|

- **零调用被稀释**：轨迹层面，"整条轨迹不调工具"在自有数据里占 24%，混入开源后整体降到 9%（750/9788）。开源"第一步直答"虽多，但几乎都是多轮里后续用户轮的回复，整条任务最后还是要调工具。这与 notool +16、零调用题去调工具 +30 对得上。
- **长思考**：开源每个调用步平均思考 842 字（自有 144 字），是考卷里复读/撞上限 +27 的最可能来源。

## 5. 结论：大包里大约有多少"问题数据"

- **Agent 侧**：问题不在于单条数据坏，而在于**分布不对**。开源轨迹占 Agent 行的 80%，而且几乎条条调工具、每步长思考，把自有数据里"不调工具直接答"和"短思考"的比例压低了。这一块直接对应考卷 −44 里的大头：零调用 +30、复读 +27、重复收尾 +53。
- **对话侧**：约 **1/3（3266 / 9834 行）** 按现在的规则不合格，坏得最集中的是 huang_sg、nemoif_chat、dsv41_zh、dsv4、st2_mtif；中文绕圈能对到两个具体来源（jackrong_zh 的开头、dsv41_zh 的起草答案）。
- mix 包两块都处理了（去开源 Agent、对话按上述规则筛到 3000 条），正式版结果三类问题都消失、通用能力全面不掉，佐证上面的归因。

## 6. 下一版调整建议

1. 开源 Agent 轨迹不要按量混。真要加，先只挑零调用 / 短思考（每步 ≤300 字）的，总量控制在自有 Agent 行的一半以内，加完先看零调用轨迹占比是否仍在 20% 以上。
2. 对话来源：huang_sg、nemoif_chat 直接不用；dsv41_zh、dsv4、st2_mtif 只取通过规则的那部分（各剩 30–50%）；wildchat_zh_mt、am_qwen3_mt、st2_everyday/sys、openqa_zh 是干净主力。
3. 混包后固定查三个数：零调用轨迹占比、调用步思考长度中位、对话不合格率，作为出包闸门。
