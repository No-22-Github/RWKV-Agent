## 4. bashprobe 原题为什么比昨天低

逐题看，昨天 3/3 的 bsh-0019（注入）、bsh-0021（选 get_weather）今天 k0 都挂了。排查：

1. **wire / 工具目录哈希与昨天一致**，模型看到的提示没变。
2. **端点前后快照一致**（引擎、模型 id、hard_max_bsz）。
3. **state 有生效**：同 4 题（0016/0018/0019/0021）各 3 次，带 state 的 bsh-0021 两种 cli 都会调 get_weather（2/3、3/3），不带 state 1/3 且会凭空编答案。
4. **新旧 cli 对照**：同一时间、同 state，bashprobe 26 题各 2 次：main cli 6、5，688cbfa1 cli 7、6。差距在已知单次极差（2–8）以内，**分不出**。

所以今天的低分对新旧 cli 都成立，不是 740ee2bd（bash 写盘）引入的。可能的原因是并发组成不同：10-13 的 bashprobe 是单独跑（26 并发），今天 k0 与 weatherprobe 同跑、对照实验四个 run 同跑，同批组成会改变输出（见历史记录的「批组成漂移」）。没有继续验证。
