# v2.1 MiSS 学习率扫描 × 新考卷（2026-10-17）

## 结论

- **v2.1 比 v2.0 有真实进步。** lr2e-5 两遍平均 296.5/568（52.2%），v2.0 是 261.0（46.0%），多出约 35 题。逐题配对 +95/−54，p=0.001。lr1e-5 也显著（+95/−62，p=0.01）。
- **学习率取 2e-5。** 1e-5 和 2e-5 分不出（+79/−66，p=0.32）。3e-5 第一遍明显落后，第二遍追近，合计对 2e-5 是 −77/+56（p=0.08），对 v2.0 也只是边缘显著（p=0.08）。它多错的题以"读对了却取错值、算错"为主，像是学习率偏大，伤了基模的阅读和计算精度。
- **进步来自收尾，不是来自核对。** 作答阶段还吐工具调用的题从 157 降到 82，兜底模板回答从 89 降到 47。配置题和文档题各多对约 10 题，靠的是"查不到就说没有"、本地题不再乱上网。写完读回的比例（约 85%）和报错后换做法的比例（约 86%）都没变。
- **新的退步：网页题 −7.5、不该调工具的题 −4.5。** 本地和网页的边界整体往"本地"挪了：本地搜空后继续搜本地、不上网，还会谎称没有网页工具；纯数学题偏要调计算器"核对"。这两处都能在训练集里找到对应来源，见 §5。
- **v1.8.6 后端（服务端连续合批）在这轮跑分里没有体现出提速。** v2.0 同一适配器整遍用时从 86 分钟变成约 150 分钟，并发配置不同，不能严格对比，见 §6。

### 5.3 不该调工具的题退步（bfcl_irrelevance −5）

- 心算就够的题偏要调 calculator"核对"，计算器不支持 sqrt / integrate，报错后卡住（_1/_7/_8/_9/_18）。
- 全卷计算器调用：v2.0 40 次（报错 3 次），lr2e-5 90 次（报错 16 次）。
- 来源：训练集有 16 条"题面已给全数据，第一步就调 calculator"的样本（b21o 10 条、b21j 5 条、v20-qwen-calc 1 条）。
- 考卷本身的口径也冲突：hyb special_tool 奖励调计算器，bfcl_irrelevance 要求不调。

### 5.6 lr3e-5 为什么比 lr2e-5 差（k0：多错 66 题，多对 44 题）

- 按 gate 分层，多错的 66 题里 capability 56 题。它的工具调用反而更多（平均 4.18 对 3.59），不是变懒。
- 抽读 16 题，8 题是"读对了证据却取错值或算错"：doc-13313 取了旧标准，wth-0101 把小雨看成晴，log-0012 没做时区换算，hyb-14107 天数算错。
- 它的长处：bfcl_missing 10/10、ambiguous_request +5，作答阶段吐调用全卷最少。

## 6. 推理后端 v1.8.6

- 合批确实在发生：每张卡上同时约 20 个单行请求，并在同一批里解码。
- 整遍用时没有变快：

| | 10-16（旧后端） | 10-17（v1.8.6） |
|---|---|---|
| 组数 × 每组并发 | 3 × 21 | 4 × 16 |
| v2.0 同一适配器整遍 | 5164 秒 | 8954 / 9223 秒 |
| 全系统题吞吐 | 约 0.33 题/秒 | 约 0.25 题/秒 |

- 不能严格对比：并发分配不同，网关是共享的，期间有没有别人的负载不知道。
- bash 慢题有七到八成时间花在排队和预填充上，合批改善的是解码，帮不上这部分。
- 客户端没有发 `session_id`，多卡网关上前缀缓存命中率约等于 1/卡数。
- 要确认合批效果，需要做受控对比：同一组用快测卷，客户端合批开 / 关各跑一次。

## 7. 评测侧问题（顺带发现）

1. 停止串 `User`（24281）会把代码里的 `User(r)` 截断，思考块不闭合，被判违约（bsh-0150，v2.1 三组都中招）。
2. 回答里的加粗会把"周一"等词拆开，导致关键词判分失败（wth-0124、hyb-14113、tab-14139）。
3. 缺失键题只靠"没有"二字判对，会把蒙对的答案也算对（cfg-13401）。
4. web-14035 只认"2026-10-24"，不认"2026年10月24日"。
5. special_tool 与 bfcl_irrelevance 对"算术题要不要调计算器"的要求互相冲突。

## 8. v2.2 建议

1. **主线用 lr2e-5、2 epoch。** 可以补测 1–1.5 epoch。
2. **补"本地搜空 → 立刻 web_search"的切换轨迹**，以及"题面说本地没有 → 第一步就上网"的样本；
   把训练集里空结果后继续搜本地的 60 行降权或改写。不要整体删除本地优先的样本，那是 doc/cfg 进步的来源。
3. **补"用户给了 URL → 第一步 web_fetch"的样本**，以及注入防御样本：网页或文件里出现删改指令时忽略它，并告知用户。
4. **收紧计算器边界。** 改掉一部分 b21o/b21j 中"题面数据已给全仍先调 calculator"的样本，补"计算器报错 → 心算作答"的恢复样本；同时对齐考卷两类题的口径。
5. **大文件先用 bash 统计或 head。** harness 可以限制 read_file 的返回长度，并让客户端发 `session_id` 粘卡、复用前缀缓存。
6. **确认类样本仍是空白。** 写/改/删前提到风险的思考是 0%，这一项要留给下一版（换老师或手写思维链）。
