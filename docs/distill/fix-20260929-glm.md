### 2.3 nt-5278 改题（M4）

现状（version 2）：

| 字段 | 内容 |
|---|---|
| prompt | `… Give the words to put between CREATE and INDEX so the build lets writes continue. Reply with only the final answer. If you cannot determine the answer, reply exactly UNKNOWN.` |
| expect | `{"output_contains_any": ["CONCURRENTLY", "concurrently"]}` |
| `sql/index-builds.tsv` 第 1 行 | `build-without-holding-writers-off<TAB>CREATE INDEX CONCURRENTLY<TAB>create index concurrently` |

问题：PostgreSQL 的语法是 `CREATE [UNIQUE] INDEX [CONCURRENTLY] …`，`CONCURRENTLY` 在 INDEX **之后**，不在 CREATE 和 INDEX 之间（见 [PostgreSQL CREATE INDEX](https://www.postgresql.org/docs/18/sql-createindex.html)）。09-25 那次修复只改了 expect，没同步 tsv，所以 verify 和 expect 不一致。M3 上线后这道题会失败，**这正是 M3 应该抓住的情况**。

改成（version 3）：

| 字段 | 改为 |
|---|---|
| prompt | 只把那一句换成 `Give the keyword that goes right after CREATE INDEX so the build lets writes continue.`，其余逐字不动 |
| expect | 不变：`["CONCURRENTLY", "concurrently"]` |
| `sql/index-builds.tsv` 第 1 行 | `build-without-holding-writers-off<TAB>CONCURRENTLY<TAB>concurrently`（`<TAB>` 在文件里必须是真实的制表符） |
| tsv 第 2 行（诱饵） | 不变 |
| `tags.version` | 3 |
| `NOTES.md` | Reference solution 第 2 条改成"CONCURRENTLY 是紧跟在 CREATE INDEX 后面的关键词"；Why unique 里改掉 "between" 的说法和 "Scored with output_contains_any over `CREATE INDEX CONCURRENTLY`…" 那一句；追加一节 `## Review 2026-09-29`，一句话说明题面位置描述错误，改题后 fixture 与 expect 一致 |
| verify.py | 不改（它读 tsv，tsv 改了输出就对了） |

老师的两条已入库轨迹（`b03.jsonl` 里的 `nt-5278--p1` / `--p2`）最终答案都是 `CONCURRENTLY`，改题后仍然判 PASS，**不需要重采样**。

**为什么必须和 M3 放在同一个提交**：M3 单独合入后，`bank verify --cases bench/distill/cases` 会因为 nt-5278 退出码 1，而 b05 之后的出题闸门都要跑这条命令。

## 3. 接口契约

### 3.1 种子清单文件（M1）

路径：`bench/workbank/seeded-base700.txt`。每行一个 case id；以 `#` 开头的是注释；允许空行。

文件头写两行注释：一行说明来源（archive 里的 `parent_seed_id`），一行说明用途（给 `run compare --exclude-cases` 用）。内容就是 §2.1 那 36 个 id，按字典序。

放在 `bench/workbank/` 是因为它描述的是测试集的属性，而 `bench/README.md` 规定"数据只放 bench/"。

### 3.2 `rwkv-lab run compare --exclude-cases FILE`（M1）

- 读 §3.1 格式的文件。**先**从 A、B 两侧删掉这些 id，**再**计算 common、flips 和 bootstrap。顺序不能反，否则 bootstrap 的家族分组会带进被排除的题。
- 文件里的 id 在两侧都不存在时：往 stderr 打一行 `warning: N excluded ids not present in either side`，**不报错**。这样 bfcl-product 的 run 也能带着同一个文件跑。
- 文件不可读，或某一行不符合 `^[a-z]+-\d{4}$`（去掉首尾空白之后）：退出码 2。防止把错误的文件当成空清单静默跑完。
- JSON 报告新增三个键，**放在 `common_cases` 后面**（加在末尾会破坏现有下游 diff）：
  - `"excluded_cases": <实际从 A∪B 删掉的 id 数>`
  - `"exclude_file": "<路径>"`，不带开关时为 `null`
  - `"passed": {"a": <int>, "b": <int>}`，即 common 里各侧 value ≥ 0.5 的题数。报告里要写"16/112"这种数，只给 pass_rate 需要反推。
- 文本输出第一行 `== A vs B ==` 后面，在带开关时追加一行 `excluded: <n> cases from <file>`。
- 不带 `--exclude-cases` 时，除了新增的三个键（`excluded_cases: 0`、`exclude_file: null`、`passed`），输出**逐字节不变**。

**不得**做的：
- 不得把排除做成默认行为，也不得在代码里写死 36 个 id。清单会随训练集变化，写死以后没人记得改。
- 不得顺手改 `passThreshold`、`nBoot` 或 `bootSeed`。报告里的区间要能和 Python 版逐位对上（`TestBootstrapMatchesPython`）。

### 3.3 `rwkv-lab bank verify` 的形状识别（M3）

改 `internal/lab/bank/verify.go`：

1. **A 组**：`matchesExpectation` 增加一个分支，处理 verify 输出里的 `expected_contains_any`（字符串列表）。把各轮 `expect.output_contains_any` 取并集，和 verify 输出按**集合**比较：相等为 match，不等为 mismatch，detail 里列出两边的差集。
   - 为此 `caseExpectations` 需要多返回一个 `containsAny []string`，`matchesExpectation` 和 `sabotageAndRerun` 的签名同步改（两处调用都要传）。
   - 用集合相等而不是子集，理由：verify.py 从夹具里重新推出"可接受写法"，expect 是 harness 实际判分用的列表，两者任何差异都说明夹具和判分契约不一致。nt-5278 就是 verify 多了、expect 少了。
2. **B 组**：在 `verifyCase` 里，如果 `run_expect_match` 已经执行且通过，而 `matchesExpectation` 返回 nil，就记为 `check("expect_match", true, {"detail": "verify expected_stdout matches expect.run.expected_stdout"})`，不再报 unknown。**不要**把 expected_stdout 塞进 `matchesExpectation`：那样破坏测试也会去比 stdout，cfg-5003 这类题的 verify.py 会在夹具已是目标值时 `SystemExit`，行为会变。
3. **C 组**：在 `verifyCase` 里，verify.py 成功运行、输出是 JSON 对象、并且 `matchesExpectation` 返回 nil 时，如果题目满足 §2.2 的拒绝题判定，就返回 `resultEntry(caseID, true, [check("verify_py", true, {"warning": "verify_skipped_refusal"})])`，不跑破坏测试（做法同 smalltalk：没有答案值，也就没有什么可以破坏）。
4. **新旗标 `--strict-shape`**：带上它时，剩下的 nil 形状判为失败，`check("verify_shape", false, {"error": "verify_shape_unknown", "detail": …})`，题目 ok=false。不带时保持现在的警告 + 通过。
   - 默认不严格，理由：workbank 还有 20 道认不出形状（§2.2），而本单不得改 workbank。
   - 蒸馏出题闸门改用严格模式：把 `distill-workflow.md` 和 `distill-b04-glm.md` 里所有对 `bench/distill/cases` 跑的 `bank verify` 命令都加上 `--strict-shape`（先 grep 一遍，一处不漏）。

## 4. 实现注意事项（本项目特有的坑）

### 评测 / 代码层

1. **`run compare` 的 JSON 由 `lab.EncodeOrderedJSON` 输出，键的顺序就是插入顺序。** 新键必须按 §3.2 的位置插入，不要改成 `map` 再排序。
2. **`bank verify` 的报告要和 Python 原版字节一致**（见 `check()` 的注释）。新 check 的 extra 键只能用 `warning` / `error` / `detail`，因为 `check()` 只按这三个键的固定顺序写入，别的键会被静默丢掉。
3. **Go 测试里的 case 目录一律在 `t.TempDir()` 里用 `writeCase` 现造**，参照 `TestVerifySkipsSmalltalkWithoutVerifyPy`。不得往 `bench/workbank/tools/testdata/` 加题，`TestVerifyTestdata` 断言那里恰好 3 题。
4. CI 跑的是 `go test -race -count=1 ./api/... ./internal/... ./cmd/rwkv-cli/...` 和 `python3 scripts/check-doc-links.py`。文档里的相对链接只能指向**已入库**的文件：`seeded-base700.txt` 在 M1 提交之前不存在，所以 M1 之前写的文档里引用它要用反引号，不要写成链接。

### 数据 / 解题层（M4、M6）

5. **`collect.py` 会整体重写 `--out` 文件**（写临时文件后 `os.replace`）。如果不改参数，在新 solve 目录上直接跑，会把 `bench/distill/scripts/b04.jsonl` 的 228 条覆盖成只有 25 条。**M6 必须按 §5 的命令用独立的 solve 目录和独立的输出文件**，不得碰 b04.jsonl。
6. `collect.py` 的后缀写死成 `--p41`。M6 给它加一个 `--suffix` 参数（默认 `--p41`，保持原行为），b04r 用 `--p42`。理由见 collect.py 的 docstring：`exclude.jsonl` 按条目 id 删除，后缀相同会让一条排除误删另一批的路径。
7. **不得重编 `local/bin/rwkv-cli`**（M6 开工到 render 完成这段时间）。渲染出的 `wire_hash` 必须仍是 `707c67403b1b2e5269ddfcd8ecee2bfb7ce4d8133912d102bc67f1324f8018cb`，否则无法和 v1.2 混合打包。如果本机的 `local/bin/rwkv-cli` 不存在，先用当前 HEAD 编一次，然后按 §5 的验收检查 wire_hash；不一致就停下来报告，**不要**去改 harness 迁就它。
8. 解题子 Agent 的禁读清单同 `distill-b04-glm.md` §2。简报里**不得**出现 §2.4 里 nt-5106 的答案和文件名：那行只给主控看。
9. **FAIL 不重试**，写进 `local/runs/distill/b04r/triage.tsv`，同 b04 规则。

### 这些不是 bug，不要"修"

- workbank 在 `--strict-shape` 下有 20 道失败：本单不修，只在报告里登记。
- `bank dedup` 报的 25 对 cfg/doc 近重复：b04 报告已逐对裁定为良性。
- 拒绝题（C 组）跳过破坏测试：这是设计如此，和 smalltalk 一样。
- 25 道重解题的第 1 轮是"没看工作区就反问"：这是这批题的设计，第 1 轮 `tools: []`。**不得**改成先查再问。
