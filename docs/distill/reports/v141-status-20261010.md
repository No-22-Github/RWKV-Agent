## 3. 为什么工作量比计划大

每道题不是一句题面，而是一个完整的小工作区，外加判据和破坏测试：

| 每题要交付 | 说明 |
|---|---|
| `case.json` | 题面、工作区 fixture、判据、tags（family / canary / task_type / traps）；b10 样板平均 6.5 KB，b12 平均 25 KB |
| `verify.py` | 对答案位置敏感，必须过 `bank verify` 的破坏测试（答案字面量 +1 或删首行） |
| `NOTES.md` | 题目意图与陷阱；hybrid 题须含 5 种改写说法 |
| 构建脚本条目 | 样板 90 题用了约 4700 行构建代码，约 50 行 / 题；b12 的 bash 题还要在 sidecar 里跑参考解 |
| 闸门 | lint、verify（含破坏测试）、五面去污染、dedup、hitcheck（web 题） |
| 老师解题 + 质检 | k=3，判分器之外必须**逐条读终答**（试跑 70 题里判分器漏掉 4 条） |

实际耗时参照：b10 试跑 70 题约一整天（含两轮盲解和返工），b12 样板 20 题约一天。
按这个速度，~1120 题是 15–20 个工作日的出题量。即使并行开多个执行 Agent，瓶颈也在「主控逐条审题 + 读终答」，压不到一周以内。
试跑里 12/70 第一轮失败，其中 9 道是判据写得过严：放量时这类返工会按比例出现。

## 4. 放量之前要先定的事

1. **训练方向变了没有。** 10-10 的复测（[think-full-20261010/REPORT.md](../../evaluations/think-full-20261010/REPORT.md)）显示基模开思考后 workbank 3.7→11.3，
   用户倾向做带思考的 MiSS 微调。如果走这条路：
   - 老师要产出思考：换成 MiniMax-M3.1-Flash（[筛选报告](../../evaluations/minimax-teacher-20261010/REPORT.md)：workbank 132/148，思考短且英文，贴近 g1k）；
     试跑的 Claude 盲解没有思考，b01–b03 的 DeepSeek 路径当时也没落盘思考；
   - 渲染要支持 think-full 形状（`corpus render` 目前只支持 g1k），`wire_hash` 会变，所有存量行都要重渲染，并补思考；
   - 终答形态规则要合并 [think-shape.md](../../evaluations/think-full-20261010/think-shape.md) 的结论（终答只给值、不包 `<answer>`）。
   题目本身（工作区、判据）两个方向都能用，**出题可以先开工，老师与渲染等方向定了再跑**。
2. **老师并发。** Flash 走 Token Plan，3 并发稳定、48 并发几乎全 429。~1120 题 × k=3 ≈ 3400 次解题，按 3 并发、每题 ~6 秒约 2 小时，可接受；更大批量需要确认额度。
3. **谁来出题。** 交接提示是写给外部执行 Agent 的，至今没有交付。如果由本仓库的 Claude 主控 + 子 Agent 出题，建议先做一批 120 题（M2 + M3，`b10a`），按 b10-scale-prompt 全流程走完、量出真实的人时，再定剩余排期。
