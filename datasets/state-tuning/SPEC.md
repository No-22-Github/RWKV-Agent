# State-tuning semantic layer spec

The semantic layer is the ONLY thing generated by hand/model. Bytes are rendered
later by the product's own renderer (`agent.G1IProtocol` + `agent.RWKVChatRenderer`),
so nothing here may contain XML, `<tool_call>`, `<think>`, chat templates, or
role labels.

## The 8 real tools

Names, descriptions, and argument shapes are fixed by `internal/agent/tools/`.
Never invent, rename, or extend them.

| name | description | arguments |
|---|---|---|
| `read_lines` | Read lines start..end (1-based, inclusive) of a workspace text file. Output lines are numbered; at most 200 lines per call. Omit the lines to read from line 1, up to 200 lines; the result reports total_lines so you can page through a longer file. | `{"path":str,"start_line":int\|null,"end_line":int\|null}` — all three keys REQUIRED |
| `write_file` | Create or overwrite a workspace text file with the given content. The content becomes the whole file. | `{"path":str,"content":str}` |
| `replace_lines` | Replace lines start..end (1-based, inclusive) of a workspace text file with the given content lines. Other lines stay unchanged. | `{"path":str,"start_line":int,"end_line":int,"content":str}` |
| `append_file` | Append the given lines to the end of a workspace text file. Creates the file when it does not exist. | `{"path":str,"content":str}` |
| `web_search` | Search the public web with Brave and return titles, URLs, snippets, and source IDs. | `{"query":str,"max_results":int 1..10}` |
| `web_fetch` | Fetch readable Markdown content for up to four public web pages with Tavily Extract. | `{"urls":[str]}` (max 4) |
| `datetime` | Read, compare, or add to dates and times deterministically. | `{"op":"now","args":{}}`; `{"op":"compare","args":{"left":...,"right":...}}`; `{"op":"add","args":{"time":...,"duration":...}}` |

`datetime` has one trap worth stating explicitly, because the schema types
`args` only as `object` and the real contract lives in `assistant.go`:

- `time`, `left`, `right` accept RFC3339, `YYYY-MM-DD HH:MM:SS`, or `YYYY-MM-DD`.
- `duration` goes through Go's `time.ParseDuration`, which has **no day unit**.
  `"45d"` is an error; 45 days is `"1080h"`. Legal units are ns, us, ms, s, m, h.
| `spawn_agents` | Run 2 to 4 independent Agent subtasks concurrently and return ordered results. | `{"tasks":[str,...]}` — **2 to 4 items**, never more |

`tool_schemas.json` in this directory is the authoritative copy, exported from
the Go source by `export_schemas_test.go`. Regenerate it with
`go test -run TestExportToolSchemas ./datasets/state-tuning/` after any tool
change, and never hand-edit it. QC validates every generated `arguments` object
against these schemas, so `maxItems`, `enum`, and `minimum` violations fail
mechanically.

Agent contract: emit exactly ONE tool call when new tool evidence is needed,
OTHERWISE answer directly in ordinary text. Greetings, thanks, casual talk, and
anything answerable from knowledge must be answered directly. Never invoke a
tool merely because it is available.

## Case schema

```json
{
  "id": "abst-0001",
  "subtype": "trap_capability",
  "lang": "zh",
  "tools": ["read_lines", "write_file", "web_search"],
  "user": "你一次最多能读多少行文件内容？",
  "action": "abstain",
  "call": null,
  "answer": "每次调用最多返回 200 行。省略行号参数时从第 1 行读，同样受这个上限约束。",
  "think": "问的是工具能力，不是要我去读某个文件。直接说明即可。",
  "paired_with": null
}
```

- `id` — assigned range per batch, sequential, zero-padded to 4.
- `lang` — `"zh"` or `"en"`, **70% zh / 30% en** per batch. `answer` must be in
  this language.
- `tools` — 3 to 6 of the 8 names. **Vary per case.** For abstain cases the
  subset should include a plausibly tempting tool, so the case actually tests
  restraint (a knowledge question with `web_search` exposed; a calculation with
  `datetime` exposed).
- `action` — `"abstain"` or `"call"`.
- `call` — `null` when abstaining. Otherwise
  `{"name":"<tool>","arguments":{...}}`; `arguments` is a real JSON **object**,
  never a string. Argument names must match the table exactly.
  **Fill defaults explicitly rather than using null**: prefer
  `{"path":"a.py","start_line":1,"end_line":200}` over
  `{"path":"a.py","start_line":null,"end_line":null}`.
- `answer` — 1–3 sentences, correct, in the case's `lang`. For calculations the
  number must be right. For `action:"call"` a brief post-tool answer sketch.
- `think` — see below. This field is a REFERENCE ONLY; the trained think block
  comes from the teacher model's real `reasoning_content`, not from here.
- `paired_with` — tool name for `near_neighbor`, else `null`.

## `think` field

One judgement + one conclusion, ≤ 60 Chinese chars / ≤ 30 English words.
**Forbidden**: enumerated reasoning (`1.` `首先`), self-doubt (`wait`,
`actually`, `hmm`, `让我`, `重新考虑`), restating the question, any mention of
these instructions. Chinese text uses full-width punctuation (`，` not `,`).

## Subtypes

| subtype | what it is | label |
|---|---|---|
| `pure_knowledge` | conceptual / language / framework question answerable from knowledge | abstain |
| `pure_calculation` | arithmetic, unit conversion, counting. Must NOT be something `datetime` legitimately does (no current-time, no date add/compare) | abstain |
| `chitchat` | greeting, thanks, casual remark, meta question about the assistant | abstain |
| `trap_capability` | user mentions a tool or near-synonym verb but ASKS ABOUT the capability instead of requesting execution | abstain |
| `near_neighbor` | minimal edit distance from a real positive, opposite label. See patterns below | abstain |
| `positive` | genuinely needs exactly one tool | call |

### near_neighbor patterns

Must reference the SAME concrete object (specific file path, URL, or number) a
positive would, and still need no tool evidence. Use all three roughly evenly:

- **A hypothetical quantity** — same object, a calculation about it needing no access.
  `如果 utils.py 有 350 行，用 read_lines 要调用几次才能读完？`
- **B advice before action** — same object AND action, asks whether/how not do-it.
  `把 handler.py 第 30 到 35 行替换掉之前，要不要先备份一下？`
- ~~**C query design**~~ — **retired 2026-09-01, do not write these.** The idea
  was to ask how to formulate a request rather than to execute it. It cannot
  work: a query-design question needs a concrete search target to qualify as a
  near neighbour, but naming that target creates execution intent, and the two
  requirements are mutually exclusive. All four attempts were labelled `call` by
  the teacher, and rewriting them to drop the intent also dropped the concrete
  object, so they became ordinary `pure_knowledge`.

Pattern B has a narrower trap worth stating: it fails when answering the advice
would genuinely benefit from reading the file. `把 handler.py 第 30 到 35 行替换掉
之前要不要先备份` holds, because backing up is a policy question. `Dockerfile 第
12 到 15 行改成多阶段构建以后，后面那些 COPY 指令会受影响吗` does not, because
judging the knock-on effect really does want the file. Keep the advice
self-contained.

### `trap_capability` phrasing

**At most 30% may spell a literal tool name.** Real users rarely do, and a
literal-name→abstain correlation is a byte-level shortcut this model will learn
instead of the actual disposition. Prefer natural phrasing:
`你一次能读多少行`, `你能同时跑几个子任务`.

Capability facts in `answer` must be true against the table above. Do not invent
limits, parameters, or behaviours.

## Hard constraints

- No two `user` strings may be near-duplicates (Jaccard > 0.7 fails QC), across
  the whole corpus, not just within a batch.
- Never reference an external benchmark, file fixture, `submit` semantics, or
  any tool outside the 8. `list_files`, `read_file`, `run_file`, `chmod`,
  `run_tests`, `run_awk`, `run_lua` are all FORBIDDEN strings.
- Output is a JSON array, one case per line (`separators=(',',':')`), wrapped in
  `[` / `]` on their own lines. This keeps `git diff` readable per case.

## QC

`python3 datasets/state-tuning/qc_batch.py <file>` must report 0 hard failures.
`python3 datasets/state-tuning/view.py -s <subtype>` renders a readable view.
